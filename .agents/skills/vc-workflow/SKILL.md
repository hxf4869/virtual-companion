# Virtual Companion 开发工作流

所有代理（Claude、Codex、agy / Gemini）在本仓库按同一流程工作。红线、授权与检查表见仓库根 `AGENTS.md`，本文件只写“怎么做”。

## 1. 接单

- 任务来源只有 `docs/planning/2026-10-31-handoff-backlog.md` 中带 ID 的条目。清单外的必要工作，先在清单末尾追加条目并写明原因，再做。
- 一次做一个 ID。需要 Owner 拍板的点在条目下写 **[问]**，继续做不依赖它的部分，不自行决定。
- 动手前只读该条目链接的文档和直接相关代码，不通读全仓。

## 2. 分工与并行

| 角色 | 负责 |
|---|---|
| Claude | 调度、拆分、代码与视觉审计、集成提交、向 Owner 汇报与提问 |
| Codex（`gpt-6-astra`，`xhigh`） | 后端、SQL / 迁移、契约、Node 服务端、出图 |
| agy（`gemini-4-argon-high`，`high`） | 前端实现；每个会话的提示词第一行写 `/boost` |

- 并行只在写入文件互不重叠时进行；每个执行者一个独立 worktree，同一文件同一时间只有一个写入者。
- 由 Claude 派发的任务：执行者只改文件、不提交，Claude 审完 diff 后统一提交推送。单独执行时按第 7 节自行提交。
- AgentBox 上外部 CLI 一律经 `ai-run` 启动，进度看日志或 tmux，不刷进对话。Mac 上使用各 CLI 的直接路径。
- 派发提示词要自包含：目标、背景、写入范围、禁止事项、验证命令、返回格式（模板见第 8 节）。

## 3. 契约先行

- 接口变化先改 OpenAPI / catalog，`specs/generated/**` 只用生成器产出。
- 迁移从当前最大版本号顺延，一个条目最多一个迁移，同步 `backend/internal/migrate/migrate_test.go` 计数并跑 RLS 测试。
- 跨端共用的数据结构，生产者和消费者在同一改动里一起改。

## 4. 实现

- 做满足条目的最小完整修改，复用现有组件、模型和流程，不顺手重构。
- 已复现的缺陷：先写会失败的回归测试，修复后转绿，并保留修复前失败的证据。
- 前端任务先读同目录的 [frontend.md](frontend.md)。
- 不删测试、不加 skip、不削弱断言、不放宽预算或阈值。

## 5. 验证（最小有效）

按改动选择 `AGENTS.md`「检查与工具链」表中的入口，只跑受影响部分：

- 受管场景只跑改动直接影响的场景，不默认跑整组 17 项。
- 性能采样在没有其他重负载时单独跑。
- 动到聊天或记忆的体验、性能时，附指标脚本前后对比（脚本由 CM 条目提供；尚未提供时标 NOT_RUN）。
- 结果如实写 PASS / FAIL / NOT_RUN；环境失败先定位原因，不直接归因环境，也不把未运行算通过。

## 6. 验收记录（一页）

只有改了 UI 才截图：用受管环境截 390 与 1440、浅色与深色，放到 `.review-queue/<ID>/`（已忽略，不提交）。设计候选图只提交到审图分支。

`.review-queue/<ID>/NOTES.md` 不超过一页，固定四段：

```markdown
# <ID> 验收
- 改了什么：<1–3 行>
- 验证：<命令 → PASS/FAIL/NOT_RUN，各一行>
- 已知差异 / 未覆盖：<逐条，没有写“无”>
- 需要 Owner 决定：<逐条，没有写“无”>
```

## 7. 进度与提交

- 进度只回填 `TODO.md` 对应主线下该 ID 的一行，格式：`- [x] <ID>（YYYY-MM-DD）：结果一句话；验证摘要；提交 <hash>`，不超过 3 行。细节放 NOTES 或提交说明。
- 需要 Owner 人工验收的条目，人工步骤未完成前不勾选。
- 本地提交后立即 `git push` 到当前跟踪分支；不 force push、不改写历史；未要求时不开 PR。
- 合并 main、部署、发布按 `AGENTS.md` 的授权执行，不因任务完成自动进行。

## 8. 派发提示词模板

```text
[/boost   ← 仅 agy]
你是<实现者/审阅者>。工作树 <路径>（<分支或提交>）。先读 AGENTS.md、AGENTS.override.md、.agents/skills/vc-workflow/SKILL.md<、frontend.md>、Backlog 条目 <ID>。
目标：<一句话>
背景：<必要事实、文件:行>
写入范围：<目录/文件>；只改文件，不提交 / 推送。
禁止：<不跑的检查、不碰的数据、红线>
验证：<命令>
返回（中文）：改动与原因；修复前失败证据；命令结果 PASS/FAIL/NOT_RUN；需 Owner 决定的问题。
```

## 9. 停止

条目完成且必要验证通过后停止，不自动开始下一个 ID。受阻时报告已完成部分、未验证部分与具体阻塞。
