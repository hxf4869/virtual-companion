# C04 / C05 真实复杂卡制作配方

这是未来获授权实施时的任务；当前仅修订配方，不执行安装或模型调用。C1 已确认；实际保护与凭据尚未配置时使用合成数据，真实用途与预算未授权时仅用固定 provider。只使用锁定的真实ST、TavernHelper、EjsTemplate和MVU，最终从原生界面导出验证后的卡。不能用自造Mvu全局对象、静态HTML或“模拟变量成功”替代。

## 1. 内容

原创角色“澄夏”，经营蓝窗书店，交流简短。用户在店内讨论一本虚构的旅行笔记。角色卡有两个开场和公开世界书；不含真人或社区素材。

状态最小化：

- trust：初始10。
- scene：初始bookshop。
- discussed_book：初始false。

状态栏显示这三项；按钮“查看当前状态”通过当前楼层 / 当前chat的真实Helper / MVU API读取，不能读取写死的本地副本。

## 2. 依赖与初始化

- 按references/upstreams.lock.json获取固定ST与扩展。
- 在官方文档 / 固定源码中确认MVU脚本安装、初始化世界书条目和模型变量更新协议。
- 从上游当前版本生成合法的更新文本，不在未核对前猜格式。
- 等待实际Mvu初始化事件 / API，不用固定sleep。
- EJS条件读取当前变量，决定下一轮是否注入一段公开说明。
- 原生正则仅隐藏显示层的变量协议，并验证发送前 / 显示处理配置不同；保留能检查的原始文本。

## 3. 固定provider响应

先返回一条普通台词，随后按实际MVU协议把trust改成15、discussed_book设true。该更新由MVU真实解析和保存。

下一轮捕获实际模型请求：

- 已有角色/用户宏被正确替换。
- 触发了书店世界书条目。
- EJS读取到true，注入预期公开片段。
- 没有未经处理的模板片段。
- 状态栏与持久数据都为15。

再提供另一个swipe，合法地把trust设为8。切换后检查只采用当前swipe状态，而不是在15上再累加。

## 4. 操作顺序

1. 纯原生基线导入卡，初始化，读取变量。
2. 发送第一轮，确认15并刷新。
3. 生成第二个候选回复，切换到8并刷新。
4. 回到旧候选，再分出新branch，验证各分支状态。
5. 编辑一条相关消息，验证适用的重算 / 失效行为。
6. 快速切换chat后等待旧异步任务，不能把旧结果写入新chat。
7. 启用本项目扩展和记忆注入，重跑受影响路径，原卡核心行为保持一致。
8. 桌面与实际目标手机浏览器各操作主要流程；窄视口模拟只作补充，状态栏、输入、停止、切卡和重新打开均可操作。
9. 集成F后复查自动保存/swipe，旧writer或旧revision不能绕过；不得用原生force强行提交陈旧状态。

原生在某个边界有已复现限制时，记录基线行为，决定最小适配或明确限制；不要伪造上游没有的保证，也不要随意重写整个变量框架。

## 5. 交付物

- 从真实ST导出的卡与相关世界书 / 正则 / 脚本引用。
- 固定依赖和bundle hash。
- 实际请求捕获（合成内容、无密钥）。
- 变量在初始化、15、8、reload、branch下的结果。
- 使用的真实浏览器和版本。
- 固定provider结果与真实模型结果分别记录。

安装组合无法运行时先定位真实版本 / API问题，可小范围调整候选版本并更新锁文件。不得无限重复同一失败尝试，也不得将复杂卡降级成普通文本卡后宣称P1完成。
