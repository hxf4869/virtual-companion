## 已确认范围与输入含义

A1 ST 主入口、B2 首版含 P5、C1 原生文件保护、D2 首版邮箱＋飞书、E3 不迁移旧聊天、F2 全保存版本检查、G2 独立用途绑定均已确认。具体模型 / 预算 / 凭据 / 收件目标是运行配置，不重新当作产品取舍。

JSON 案例是应用无关的输入、步骤与预期，不是 ST、Go 或 MemoryCore 已实现的 API payload。Agent 应映射到实际接口验证，不能写一个只识别 fixture 的假引擎。所有运行数据用独立合成 owner / instance；真实私人数据先满足保护配置，真实调用和通知先满足执行会话的相应授权与配置。

F1 不再实现，B06 保留历史规格并注明 NOT_APPLICABLE；其余适用案例保持 NOT_RUN，不能把未跑写成通过。未采用外部记忆引擎时不为测试额外引入一套引擎。

## 记忆与时间

M01 保留 101 条已提炼记录，检验确定性召回，不证明 LLM 提取效果。目标来源为 2026-10-20，事件明确为 2026-10-30，查询于 2026-10-27 直接问 10/30 的计划。

M11 采用明确 ISO 周语义：来源 10/20 的“下周五”是 10/30；查询 10/27 的“下周五”是 11/06。抽取延迟、重试和服务器时区变化不能移动计划。M12 缺失来源时区且语义不明确时保持 needs_clarification，不创建可触发提醒。

source 时间、记录时间、事件日期 / 时间和提醒时间分别表示。只知日期就保留 date 精度，不默认凌晨零点。样例冻结时间与时区不代表替所有业务选择时区。

## 生命周期重点

- **B03**：旧聊天不搬入 ST，旧源派生内容不隐式激活，原数据不误删；保留域导出 / 删除责任仍明确。
- **B04/B05/B07**：手机写入并 ACK 后电脑旧完整快照被拒；普通保存、MVU、删除、改名、分支、导入和群聊都受 F2 保护，同端迟到结果也不能覆盖。
- **R01–R05**：ST 已保存编辑 / 删除，浏览器通知前关闭，重开、重连、跨 chat 检索和后台准备能对账；读取失败不误删，旧结果不复活。
- **D01–D06**：C1 的实际存储保护、跨域导出 / 删除、文案能力一致、备份恢复不复活；原文仍在当前历史时，“删除记忆”不能声称模型不再看到。
- **MODEL01–MODEL08**：G2 独立绑定、共享配置修订、三种真实协议、流式 / 工具 / 取消、能力状态与上下文边界；缺用途 / 费用配置时不新增真实调用。
- **A04/N01–N03**：邮箱与飞书各自验证手机关闭网页的接收。逻辑事件去重与外部不确定投递分开，可能重复就如实说明，通知成功不能替代 ST 保存 ACK。
- **UI01–UI03**：设计规范、Stitch 稿与真实 ST 页面一致；手机实际操作和统一模型配置可用，不以截图或空下拉框代替运行能力。

固定 provider 与本地 SMTP/Webhook 模拟接收端可用于确定性验证；其成功不能计为真实手机收到或模型效果通过。测试按当前阶段选取受影响案例，已有有效证据可复用。

## 剧情

P5 是 B2 首版必需项。GM truth 与 private knowledge 用于规则层构建角色视图；唯一标记辅助定位泄漏，还需核对来源及语义。三协议最终出站请求都要检查，不仅检查转换前的公共结构。

玩家取得线索后需实际向周澈出示，才能归还钥匙；完整七步路径用于确定性规则验证。剧情规格自身不证明游戏引擎或真实叙事已运行。陪伴角色入局后的虚构身份与秘密不自动写进现实画像，结局共同经历摘要由用户选择保存。
