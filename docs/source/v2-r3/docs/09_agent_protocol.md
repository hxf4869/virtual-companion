# Codex / Claude Code 工作规则 · R3

## 1. 当前任务与未来实施

本轮只修订完整执行包，不修改项目代码、启动应用、调用真实模型、发送邮件 / 飞书或部署。包中包含未来启动提示词，本轮不执行。

用户已确认 1A / 2C / 3C、A1 / B2 / C1 / D2 / E3 / F2 / G2、邮箱＋飞书、设计规范→Stitch→前端、三协议模型配置和彻底重构权限。不存在等待 A–G 的产品阻塞；具体模型 / 凭据 / 预算是运行前设置。

用户把启动提示词作为“开始实施”指令提交后，按已确认范围连续推进，不再次询问同一批产品选择，不每阶段等待“继续”。只收到 ZIP 或要求审查文件时仍以实际任务为准。

## 2. 进入仓库后

读取 AGENTS / CLAUDE / PRODUCT / TODO、相关 ADR 和当前 Git 状态，随后读本包 START_HERE、DECISIONS、MASTER_PLAN、DESIGN、工作计划和当前专题。保护未提交工作，核对当前 HEAD 与审查基线的差异；不回退用户后续修订。

把已确认 V2 取舍合入现有 PRODUCT、合适的一份 ADR 和 TODO。旧 Go-only、单角色、旧前台 / 小程序、禁止通知或迁移相关约束若与新指令冲突，准确替代对应条款并保留历史原因；不为了清理把所有原有规范抹掉。

原代码可按模块彻底重构。先列简明“复用 / 改造 / 替换 / 删除”依据，优先真实在用能力与数据职责；没有继续使用者的旧 API 和双运行层可移除。旧数据、账号及密钥保管不能因为代码删除而失去责任。代码重构不自动授权清库、生产部署或外部发布。

## 3. 先查询，再开发

新增模块、准备换方案或遇到架构性阻塞时，先查本仓库实现与依赖，再查官方规范和 GitHub 源码。优先能直接使用的成熟部件、扩展接口及许可允许的复用。决定自研时说明缺口；同一版本已有调查直接沿用。

资料已足以确定“怎么接、缺什么、如何验证”就进入实现。不无限选型、不因为语言统一重写 ST、不为了可能出现的渠道或记忆引擎添加空适配器。

MemoryCore、Pi、SDK 与扩展版本属于工程验证，不新增用户投票。多个独立子任务可按环境并发能力分工；共享决定、模式迁移、上游补丁和最终集成顺序处理。

## 4. 设计与前端

先完善 DESIGN.md，再用 Stitch 产出对应桌面 / 手机稿，最后实现用户页面。已有 ST 宿主技术验证、后端与设计可以并行；不以缺设计工具为由停止全部独立工作。

复用 ST 主题、组件、事件和扩展页面，保留目标复杂卡真实行为。Stitch 产物记录实际项目 / 页面来源，不能把任意截图或孤立 React 页面当成已完成集成。密钥和私人聊天不进入设计稿。普通设计细节按规范推进，只有实质产品变化才再讨论。

## 5. 数据与可靠性边界

- ST 保存原始聊天，Go 保存长期领域状态；同一前台回合只有一个生成链，Go 不并行写 JSONL。
- F2 对全部保存路径原子检查加载基线 revision，含脚本 / MVU、swipe、群聊、删除、重命名、分支、覆盖导入；force 不绕过。保存冲突保留草稿，不自动合并剧情 / MVU。
- 浏览器事件可漏报；来源对账覆盖打开 / 重连、跨聊天候选、摘要 / 画像、后台准备和提交。暂时不可读不当成已删除，旧任务不能复活失效来源。
- C1 已接受 ST 明文边界，Go 字段保护、密码＋TOTP、磁盘 / 备份措施仍准确落实；实现允许重构。
- E3 不迁移旧聊天、不要求旧历史前台。旧数据保管和导出 / 删除办法仍可执行，旧派生记忆不偷偷混入 V2。
- 数据权利覆盖 ST / Go / 所选引擎 / inbox / 通知任务 / 导出对象。记忆删除、原文删除、后续上下文和备份清理不混淆。
- 相对日期使用来源时刻与时区，查询有自己的基准；不因异步提取或重试移动计划。

## 6. 模型与通知

三协议首版都要可配置并有代表性验证：Anthropic Messages、Chat Completions、Responses。复用现有实现与成熟 SDK，协议缺口作最小适配；不以三个下拉选项代替功能。

G2 按用途固定绑定。前台换模型不改独立后台；编辑共享 provider / profile 时显示影响用途。ST 原生设置修改也要同步实际前台版本，运行中的请求使用固定快照。支持声明与已验证能力分开，不静默降级或换收费模型。

具体模型、Key、真实验收总预算和后台日预算未给定时不调用真实付费模型。保存配置不自动测试；可先用固定 provider。实际费用涵盖工具后续、扩展附加、提取摘要、重试和 embedding；价格未知不按免费处理。

首版通知只做邮箱＋飞书，两者实现及手机接收都要验证，可独立启用。SMTP / Webhook 接受不是手机显示、用户已读或 ST 保存 ACK。结果未知的远端重试不假称 exactly-once；有界重试与用户可见状态即可，不新建消息中台。真实发送使用用户明确配置且获准的目标。

## 7. 持续推进与最小阻塞

完整首发包含 P5；不能用 P0–P4 的演示替代完成。阶段是技术依赖而非审批点。

缺运行配置时，说明“哪个操作缺什么”，继续其他独立任务。需要真实费用、外部消息或生产动作而当前授权不足时，先完成可评审的配置与方案，再一次说明所需范围；不要要求用户先给模型 Key 才开始所有开发。

不为每个函数、依赖或视觉细节申请确认。不新增与当前需求无关的防御层、未来适配层、复杂权限平台、K8s、多 Agent 调度中台或通用插件市场。

## 8. 验证与记录

修改完成后做一次与风险相称的必要验证；失败后只重验受影响项，真实边界变化才扩大回归。不为文字 / 样式的小改动反复跑全表、压测和多轮审计。

静态源码、固定 provider、真实浏览器、真实模型、实际手机通知、性能与恢复分别记录。用 NOT_RUN / PASS / FAIL / BLOCKED / NOT_APPLICABLE；B06 因 F1 未选可不适用，缺 Key / 预算不能伪装成通过。没有复现就称静态风险。

长期状态只进原 TODO 与必要 ADR；DECISIONS 与 JSON 是同一选择的可读 / 机器表达，不是第二套进度。中断前记录当前任务、配置版本、已验证范围、费用 / 未结算额、阻塞和下一步，新会话据此继续。

当前 R3 完成指材料完整交付。未来应用完成要有可操作页面、真实持久链路、所需验收和运行手册，不能只提交接口、空壳或文档。
