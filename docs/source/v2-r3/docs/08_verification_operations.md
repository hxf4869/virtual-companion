## 4. 性能与模型费用

### 4.1 先拆分实际时延

对同一 ST 版本、同一卡、同一模型参数，比较新增扩展关闭 / 开启：

- 用户发送到模型请求开始：上下文、来源核对和召回开销。
- 请求开始到首个可见 token：供应商与模型首字。
- 首字到完整回答：输出长度与生成速度。
- 模型调用数：主回复、工具、MVU 附加请求、摘要、提取、去重、embedding 分别计数。
- 后台任务耗时与积压：整理是否落后，配置 / 预算暂停原因是否可见。
- 保存、F2 版本冲突、inbox 确认：新增耗时与失败恢复。

先做一组固定交互的分段记录，报告样本数、模型、上下文长度和环境；少量烟测不包装成可靠 p95。出现具体尾延迟风险后才扩大样本。

结构目标：前台不等待整套提炼 / 构图；同一回合不重复调用 ST 与 Go；只询问一个 NPC 不固定唤醒全部 NPC；来源核对按本轮候选依赖去重批量进行，不每轮扫描所有历史；流式可取消，取消后的旧结果不写回当前分支。普通陪伴可明确跳过无法核验的记忆，严格剧情保持知情边界。

固定 provider 的吞吐只反映对应运行路径；真实模型用少量已授权交互核对体验。发现问题优先处理重复请求、同步提炼、无效上下文、队列和扫描，不据语言标签推断性能，不为个人产品无止境压测。

### 4.2 真实调用的配置与预算验收

G2 配置按用途解析：前台、提取 / 摘要、后台问候、剧情导演 / NPC、embedding 分别明确执行方、profile_id、config_revision、模型 ID 和凭据权威。前台换绑不影响独立后台绑定；修改共享 Provider/Model 显示受影响用途，实际下一次请求与统一入口一致。运行中 run 保持快照，凭据撤销阻止后续使用，超出允许用途 / endpoint / model 或预算的请求暂停。

三协议分别验证实际消息格式与事件处理；Chat Completions、Anthropic Messages 的原生路径优先复用，Responses 适配不得仅替换 URL。MODEL06–MODEL08 使用 [model_profiles.json](../fixtures/model_profiles.json) 及本地固定 provider 先证明协议，真实供应商差异以明确能力范围报告。图片、视频、PDF、结构化输出、原生搜索和推理参数不是仅凭用户勾选即已支持，未验证能力清楚标识。

一次真实验收总预算与日常后台预算分开，保留币种、允许用途和调用边界。每次真实工作流计入全部外部调用，包括扩展额外请求和失败重试。无法覆盖额外调用计量时关闭那条可选调用路径，不能仅计算主回复。

在支持的调用边界发请求前原子预留保守额度，完成后结算；并发任务使用同一额度，超时保留待核对费用，重试重新计量。缺授权、达到上限或无法按所授权边界可靠估算时不发新请求。取消能停止后续请求，不能撤回已发生费用。

请求 / token 限额不等于供应商精确账单上限。价格变化、usage 缺失和在途请求均需如实报告；若用户要求强金额上限，应核验供应商实际支持的账户 / 项目限额并配合使用。不能因后台有 API Key 或旧配置，就把新增用途和持续运行视为已获费用授权。

整体技术方向为原生 ST Node 主入口、Go companion service、PostgreSQL 和必要反向代理；MemoryCore 仅在对照选定后增加。旧 Go 模块允许彻底重构，保留所需能力及数据责任，去掉无用模块与未来适配代码。浏览器首发，旧聊天不迁移，C1/F2/G2 已明确；不为旧历史强制保留 Vue 主入口。

实施后交付真实可用的启动 / 停止 / 日志命令。配置至少包括：

- 上游固定版本、扩展和必要补丁、支持的全部写入口。
- ST 数据卷、Go 数据库、内部桥接凭据、owner / ST 账号映射与已有密码＋TOTP 边界。
- C 的数据保护清单、密钥保管、自动备份和导出对象处理、备份保留期。
- 各模型用途绑定及版本、G 的预算和授权状态；未定项清楚显示。
- 来源对账、后台并发、主动开关、时区和 quiet hours。
- 邮箱 SMTP 账号 / TLS / 发件与收件目标，飞书 Webhook 群目标 / 签名凭据；按角色启停、预览内容、失败提示和跳转地址。真实目标/付费发送服务只在实际配置授权后使用。
- E3 旧存储保留位置、导出 / 删除处理入口或离线操作步骤及其在线 / 离线状态；不需要旧聊天导入 / 续聊映射。

健康依赖确定启动顺序，不使用任意 sleep；清理脚本不默认删除数据卷。环境不足时记录准确错误，不把示意命令写成实际存在的命令。远程部署仍按执行会话已有授权；本次只更新文档。

## 6. 当前使用与数据权利边界

ST 服务端插件不是隔离沙箱。首版本人自用、锁定可信插件；保留 Go 密码＋TOTP、ST CSRF 和会话机制，内部业务接口 / PG 不公开。ST 默认用户或 req.user 不能证明实际认证。P1 隔离开发临时登录方案不能替代正式入口的完整校验。

C1 已明确接受 ST 进程可读的原生文件；加密磁盘 / 卷和备份保护不等于字段加密。保留 Go 字段保护能力，向量、图结构、元数据、外部引擎派生文本和临时副本逐项说明，不把可检索表示当加密。真实私人数据接入前实现并验证所声明保护及密钥 / 备份参数；不实施未选 C2 的全 ST 应用层加密。

导出和删号由 Go 复用现有任务编排，ST 插件与所选记忆适配器各清理其拥有的数据；每域完成条件明确。ST / 外部引擎离线时保持待处理，全部承诺在线数据域确认后才能报告在线删除完成；备份按独立保留状态说明。

删除长期记忆不自动删除 ST 原文，原话仍可能进入当前聊天上下文。删除原文、排除后续模型上下文和清理备份是不同操作；没实现上下文排除能力时，文案应直接说明限制，不能以“已彻底忘记”暗示该能力。已经发送给模型服务的请求不能由本地删除追溯收回。

官方边界参考：[Multi-user](https://docs.sillytavern.app/administration/multi-user/)、[Server plugins](https://docs.sillytavern.app/for-contributors/server-plugins/)。技术风险以设计与静态证据描述，不称已运行泄露或已复现数据丢失。

### 6.1 邮箱与飞书的完成含义

首版两条通知能力都必须可用，用户可按角色选择启用一个或两个，不强制每个事件双发。SMTP 和飞书群 Webhook 是本包工程方案；账号、目标、签名和手机权限在运行配置时完成。群 Webhook 推送与完整双向聊天是不同范围，首版仅要求通知与回到对应会话的链接。

N01/N02 用本地模拟接收端先核对正常、业务错误、限流和确认丢失；A04 再分别用真实目标观察关闭网页后的手机通知。SMTP 接受、平台 message ID / 成功码均不证明终端显示。无端侧回执时“手机收到”只能记录实际观察，不能自动写入一个虚假的送达字段。

应用层对同一逻辑事件去重，投递结果未知时有限重试；外部服务不提供足够幂等或查询语义时可能重复，报告这一限制，不为消除它搭建通用消息平台。通知成功不能替代 inbox 的 ST 保存 ACK；waiting-host 的通知应说明需要打开聊天继续，不能说依赖浏览器的复杂卡回复已完成。删除与取消只阻止后续受控发送，不承诺撤回已到邮箱或群里的内容。

## 7. 备份与恢复

备份覆盖 ST 原生数据、自动聊天备份、secrets / 迁移副本、配置与扩展锁定信息，以及 PG、映射、必要外部记忆数据和最小删除标记。备份内容与密钥分开保管；明确保留期限，不能将旧明文副本遗漏在声明范围之外。数据导出同样是敏感副本，沿用一次性下载、有效期和清理要求。

C1 验证磁盘 / 卷和加密备份及真实剩余边界；Go 字段加密随实际重构实现验证。确认各密钥缺失时的恢复限制，不把不曾实施的密钥销毁声称为删除。

将来只需在隔离副本做一组覆盖实际范围的恢复演练：

1. 产生聊天、记忆、pending inbox、两渠道投递状态、后台任务和 B2 首版剧情状态。
2. 在短暂一致的写入窗口按真实说明备份，记录版本、数据范围和删除标记截止点。
3. 备份后删除一条已派生记忆的聊天 / 来源，并完成一次代表性的跨存储清理，保留最新最小删除标记。
4. 将删除前快照恢复到独立卷 / 数据库，保持查询、生成和任务关闭；先应用备份之后的删除标记，执行对应清理和来源对账。
5. 确认旧内容不会重新获得检索资格或由任务重建，再验证 owner / chat / instance、当前 swipe / branch、剧情、inbox 和任务恢复；已确定的通知接受状态不因重启无条件重发，不确定结果保持明确说明。
6. 标明仍在保留期内的离线 / 不可变备份及预计清理时间；不得把“在线数据已删除”写成所有历史副本立刻消失。

恢复流程必须能取得不随旧数据回滚的最新删除记录；缺失时不能直接把旧快照恢复为可用私人环境。无需建设跨机房容灾或完整事件平台，复用现有持久删除意图和备份程序。

上游升级只重跑受影响 fixtures。应用回退与数据恢复分开记录，不承诺所有迁移可自动降级，也不通过覆盖原数据来做恢复试验。
