## P0：基线、重构边界与设计准备

### W01 盘点现有工程与可复用资产

- 在实施会话读取 AGENTS / CLAUDE / PRODUCT / TODO、相关 ADR、当前 HEAD 与未提交改动，保护已有工作。
- 检查 Go 的认证、关系、任务、字段加密、导出 / 删除等能力，逐模块决定保留、重构或删除。用户已允许彻底重构；不以“复用”为由强制保留差实现，也不在新旧路径之间永久堆兼容层。
- 先查本仓库、官方文档和 GitHub 的成熟实现，记录本模块采用 / 参考 / 不采用的简短理由后开发；不为将来可能支持的渠道或引擎先写空接口与 stub 适配层。
- 只读盘点旧聊天、来源、记忆、任务、导出对象及备份，明确其保留位置和权利处理入口。E3 不迁移旧聊天、不建专门旧历史页面，不代表可清库或自动删旧数据。
- 旧聊天派生的记忆 / 摘要 / 跟进默认不自动进入 v2；来源未核验时隔离保留，不能绕过“不迁移”偷偷把原内容带入新模型上下文。

### W02 写清决定、锁版本并完成设计规范

- 将已确认选择同步到现有 ADR / PRODUCT / TODO，移除与 A1/B2/C1/D2/E3/F2/G2 冲突的强制旧条款；具体 SDK、MemoryCore、Pi 与扩展版本由工程核验决定。

- 核验上游源码、许可、实际运行版本与补丁，不默默升级整个依赖组合。
- 按 [DESIGN.md](../DESIGN.md) 固化设计语言、组件、状态和手机布局，再配置 Stitch 并生成主要桌面 / 手机页面。记录可复用的设计来源与页面对应关系；本轮包内规范不冒充已生成的 Stitch 稿。
- 设计成果进入原有实现任务，不增加独立进度系统。前端成品应在对应设计稿形成后实现；后端调研、固定 provider 和复杂卡兼容验证可并行。
- 将模型用途、配置 revision、真实验收总预算 / 币种、后台日预算、通知账号 / 接收目标和备份策略列入运行配置；未给定时留空，不自动使用已有密钥付费或发真实通知。

**P0 退出**：已确认选择与旧条款对齐；重构范围、复用依据和设计规范可供执行。设计和运行配置的待完成状态如实记录，不要求先提供全部生产配置才允许继续独立工作。

### W06 来源对账、E3 和跨域数据权利

- 来源以稳定 chat/message identity、swipe/branch 和持久 revision/hash 登记，接收事件与保存完成分开。
- 保存事件加速＋服务端读回对账：打开 / 重连、候选检索 / 摘要依赖、后台生成和提取提交都核验；被修改的原聊天未重开，也不能继续被另一个聊天召回旧来源。
- 区分成功读取、确认删除、重命名和读取故障，空数组不能直接当删除。发现修订先失效旧事实 / 摘要 / 画像 / 跟进，再异步重建；旧提取提交复核 revision 与删除代次。
- E3：不导入旧聊天、不转换旧分支、不做旧会话续聊。明确旧数据保留位置、访问关闭方式、导出 / 删除责任（可通过已有工具或离线处理步骤，不强制常驻旧服务）；旧来源无法核验的派生数据不自动激活。B03 验证没有隐式搬运或误删。
- 复用或重构现有 Go 导出 / 删除编排，增加 ST 及已选外部引擎分项；覆盖旧数据保留域、新原文、派生记忆、快照、inbox、通知任务、导出对象和备份说明。
- 删号先登记持久意图，保留清理定位并阻断新写入 / 模型 / 投递；逐域完成才报告在线删除成功，离线旧存储或引擎保持 pending。
- 产品文案区分删除记忆、删除原文、排除后续上下文和备份期限；未实现最终请求排除时，不展示虚假的“彻底忘记”承诺。
- 交付 B02/B03、R01–R05、D02–D05；未采用引擎的对应子域可注明不适用，后续采用时补齐，不能永久忽略。

**P2 退出**：F2 全路径保护有效；来源漏报可恢复；不迁移旧聊天且权利责任明确；认证、导出和删除覆盖新宿主。

## P4：主动陪伴、邮箱 / 飞书与有限工具

### W09 跟进、时间与 G2 后台配置

- 复用或重构持久任务，按角色启用、quiet hours、频率以及已解决 / 已问过取消规则。

- 区分 server companion profile 与复杂卡 waiting-host；浏览器离线时不宣称前端脚本已执行。
- G2 使用用途固定绑定。前台切换模型不会自动改后台；更新共享 Provider/Model 本身会影响引用者，应显示受影响用途并在下次 run 解析新版本。
- 运行中 run 使用不可变配置快照；配置不一致、凭据撤销、用途 / 费用未配置时暂停相关请求。费用涵盖提取、问候、重试与必要 embedding。

### W10 Inbox 交付与邮箱＋飞书通知

- 依赖 W05 全保存保护。领取锁只约束投递竞争；保存 inbox_event_id、chat/instance/branch、来源 revision 与消息映射，真实保存核对后 ACK。
- 保存后 ACK 前崩溃先查重；完成 B04 联合验收：手机保存 ACK 后，电脑旧完整快照被 F2 拒绝。用户合法删除 / 回档更新链接状态，不自动补投。
- **首版两条渠道都实现并验证：邮箱、飞书。** 工程默认 SMTP＋飞书群自定义机器人 Webhook；先查现有邮件能力 / 成熟库与官方 SDK / 文档，再做最小接入。Webhook 群目标、签名与收件人属于运行配置。
- 一个通知事件按角色已启用的渠道生成独立投递记录，不强制双发；支持启停、quiet hours、频控、失败重试、失效配置提示和返回会话链接。飞书群成员可见内容，默认只发必要提醒；正文预览需在渠道设置中明确打开。
- 平台接收与手机显示分开；SMTP 接受不等于邮件已到收件箱，HTTP 200 不等于飞书业务成功。重复 job 本地去重；外部已接收但结果丢失时标记 unknown，按有限重试处理并如实说明可能重复，不能承诺跨外部服务 exactly-once。
- 应用未读、ST 保存、渠道接受、手机显示和已读各自记录；通知成功不能代替 ST 保存 ACK。网页关闭时可先通知已持久 inbox，点击后再按 F2 写入 ST；waiting-host 通知应说明需要打开继续，不能声称离线已执行复杂卡脚本。
- 首版不增加 Web Push、微信、企业微信、QQ 的适配器或占位框架。SMTP 服务费用等未配置时不擅自开通收费服务。
- 完成 A04 与 N01–N03；真实通知须在执行会话已授权的账号、目标和合成内容范围测试，本轮包修订不发送消息。

## P6：体验、性能与交付

### W15 完整界面、手机与必要性能

- ST 内统一角色 / 聊天、记忆、inbox、剧情、模型和通知设置；按 DESIGN.md 与 Stitch 稿检查完整流程及空、加载、失败、冲突状态。
