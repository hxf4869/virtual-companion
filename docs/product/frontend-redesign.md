# 前端重做：产品与体验骨架

> 状态：2026-09-01 设计基线
> 性质：重做，不是沿用旧页面做视觉重构。现有代码只用于确认接口和已有能力，不能作为新版页面结构、
> 文案或视觉权威。

## 1. 文档权威与冲突处理

- 产品范围、准入规则和禁止项：以根目录 `PRODUCT.md` 为准。
- 页面职责、流程、状态和文案意图：以本文为准。
- 颜色、排版、组件、布局和跨端实现约束：以 `frontend/DESIGN.md` 为准。
- 已验收代表页面的构图：以 `docs/design/stitch-reference.md` 中标记的 Stitch 页面为参考。
- Stitch 不能新增产品行为；旧代码和历史规划不能推翻以上文件。

## 2. 重做目标

新版前端只解决三件核心事情：

1. 用户能顺利进入产品。
2. 用户能立即继续或开始一段对话。
3. 用户能理解自己的账号和当前状态。

每个页面只有一个主要任务。内部能力、保护机制和异常细节按需要出现，不能永久占据首页、聊天页或
登录页。任何元素如果不能帮助用户完成当前任务，也没有真实数据消费者，就不进入页面。

## 3. 页面地图

### 3.1 未登录与准入

- 登录：账号（用户名或邮箱）、密码。
- 验证登录：6 位身份验证器验证码；恢复码为次级入口；完成验证后可以选择信任当前设备 90 天。
- 注册暂未开放：登录页内的说明，不单独做营销或等待名单页面。
- 未来注册：填写账号 → 邮箱验证码 → 等待审核。
- 首次安全设置：绑定身份验证器 → 验证一次验证码 → 保存恢复码。

登录和注册流程不显示底部导航。

### 3.2 消费者端

- 首页。
- 全部会话。
- 聊天。
- 我的。
- 账号安全的必要子页面。

底部导航固定为三个入口：**首页 / 聊天 / 我的**。“全部会话”属于聊天域内的二级页面。

- 点“首页”回到首页。
- 点“聊天”打开当前或最近一段对话；没有会话时进入新对话空状态。
- 点“我的”进入账号与设置。

### 3.3 管理后台（仅 H5）

- 注册审核。
- 账号。
- 模型与路由。
- 运行状态。

消费者端与后台共用品牌基础色和文字气质，不共用页面骨架；后台不进入微信小程序构建。

## 4. 账号状态与去向

| 服务端事实 | 用户进入后看到什么 | 可以聊天 |
| --- | --- | --- |
| 注册关闭 | 登录页显示“注册暂未开放” | 否 |
| 已注册、邮箱未验证 | 继续完成邮箱验证 | 否 |
| 邮箱已验证、待审核 | 等待审核页，说明当前状态 | 否 |
| 审核通过、未绑定身份验证器 | 首次安全设置 | 否 |
| 账号正常、已绑定身份验证器，无有效可信设备 | 完成身份验证器验证后进入首页 | 是 |
| 账号正常、已绑定身份验证器，有有效可信设备 | 密码正确后直接进入首页 | 是 |
| 账号被停用 | 说明账号当前不可用及可行下一步 | 否 |

前端不根据本地缓存猜测准入状态，也不先进入聊天再弹出多层拦截。服务端返回什么状态，就把用户带到
对应的一张页面。

## 5. 页面合同

### 5.1 登录

**目的**：用最少信息完成第一步身份确认。

- 页面标题使用“登录”。
- 两个持续可见的字段标签：“账号”“密码”；账号接受用户名或邮箱，不能只靠占位符充当标签。
- 唯一主按钮：“继续”。提交成功后进入验证登录、首次安全设置，或在可信设备有效时直接进入首页。
- 密码可见性切换必须有文字语义，不能只显示一个难猜的图标。
- 注册关闭时只显示：“注册暂未开放。”不显示失效的注册链接。
- 辅助内容最多保留找回密码和“AI 陪伴者 · 非真人”。
- 错误文案说明用户下一步，例如“账号或密码不正确，请重新输入”，不显示状态码和原始接口错误。

### 5.2 验证登录

**目的**：完成日常登录的第二步。

- 标题：“验证登录”。
- 说明：“打开你的身份验证器，输入 6 位验证码。”
- 使用真实、可聚焦、可粘贴、支持系统自动填充的一次性验证码输入；视觉上可以分成六格。
- 主按钮：“验证并登录”。
- 次级入口：“使用恢复码”；帮助入口降低视觉权重。
- 提供默认未选中的“信任此设备 90 天”选项；它只跳过这台设备后续登录的验证码，不跳过账号和密码。
- 验证错误保留已输入状态并说明“验证码不正确，请重新输入”。
- 不把这一步称为短信验证码、设备验证或绑定设备。

### 5.3 未来注册与等待审核

**目的**：让用户知道申请是否完成、为什么还不能聊天。

- 注册只在服务端开放后出现入口。
- 注册表单收集邮箱、密码和邮箱验证码；不收集当前业务不使用的资料。
- 提交后进入独立的“等待审核”页，清楚说明“邮箱已验证，账号正在审核；审核通过后才能聊天”。
- 等待页不展示可输入的聊天框，不循环弹窗，也不显示内部审核规则。
- 刷新状态是次级动作，前端不得伪造预计审核时间。

### 5.4 首次绑定身份验证器

**目的**：完成账号安全设置，并确保用户能够在下次登录时使用。

- 先解释用途，再提供二维码和不能扫码时使用的密钥。
- 用户输入一次 6 位验证码后才算绑定成功。
- 恢复码只在成功后展示，要求用户保存，但不制造恐慌式文案。
- 确认验证码时同样可以选择信任当前设备 90 天，默认不选中。
- 主动作按顺序为“验证并开启”与“我已保存，进入首页”。
- 完成后由服务端自动创建唯一默认陪伴关系；用户直接进入首页，不经过创建陪伴者或选择人格页面。
- 除已确认的可信设备外，不增加跳过验证或前端本地模拟的替代流程。

### 5.5 首页

**目的**：让用户回到陪伴关系，而不是浏览功能菜单。

从上到下由以下内容组成：

1. 简短问候和陪伴者身份，不展示后台状态。
2. “继续上次对话”主卡：对话对象、最后一句自然语言摘要、时间和明确主动作。
3. “最近对话”紧凑列表，默认少量展示。
4. “全部会话”文本入口。
5. 三项底部导航。

没有历史会话时，主区域改为“开始第一次对话”，不制造示例会话或假摘要。首页可以有温度和适度视觉
丰富度，但只能使用真实内容；未来功能准备好之前不放入口或占位卡。

### 5.6 全部会话

**目的**：快速找到并继续过去的对话。

- 标题：“全部会话”。
- 列表按最近活动排序，每项只显示自然语言摘要和时间。
- 会话较多时提供“搜索对话”，搜索结果仍使用同一列表样式。
- 空状态分别说明“还没有对话”和“没有找到相关对话”。
- 不显示会话 ID、消息数量、模型、Token、记忆状态或路由状态。
- 删除、导出等低频能力只有在真实实现并单独确认后才出现，不为未来预留图标。

### 5.7 聊天

**目的**：安静、连续地完成文字对话。

- 顶部只保留返回、陪伴者名称和低权重的“AI 陪伴者 · 非真人”。
- 陪伴者消息使用开放式排版；用户消息使用轻量气泡，不把每条消息都做成卡片。
- 输入区包含多行文本输入和清楚的发送动作；键盘、输入区与底部导航不能互相遮挡。
- 回复中显示“正在回复…”，不展示推理过程、模型切换或流式协议。
- 发送失败显示“没发出去，点此重试”；用户原文必须保留。
- 无网络时只给与当前动作有关的说明和重试，不展开工程诊断。
- 待审核、停用或未完成身份验证器绑定的账号不能进入可发送状态。

### 5.8 我的

**目的**：完成账号与低频设置，而不是复制后台。

- 顶部显示账号的可识别信息，例如邮箱。
- 分组最多为“账号”“安全”“关于”。
- 安全摘要使用“身份验证器：已开启/需要设置”等用户语言。
- 账号安全中可以查看可信设备的最近使用和到期时间，并撤销单台设备；不新增顶级设备管理页。
- 退出登录位于页面底部，危险动作与普通设置分开。
- 没有真实消费者的旧功能不进入列表；不显示模型、路由、运行探针或原始账号 ID。

### 5.9 注册审核后台

**目的**：管理员快速判断并处理待审核账号。

- 左侧是待审核队列，右侧是当前申请详情；桌面端不使用一屏多层弹窗。
- 队列只显示邮箱、邮箱验证状态、申请时间和审核状态。
- 详情说明审核通过后的真实结果：用户首次登录仍需绑定身份验证器。
- 页面主动作是“通过审核”，次级危险动作是“拒绝申请”。
- 不展示没有决策价值的 KPI、趋势图、风险分数或假审核时限。

### 5.10 其他后台页面

- **账号**：账号列表与详情；显示准入状态、身份验证器状态和必要管理动作。重置身份验证器必须清楚说明影响并确认。
- **模型与路由**：只面向管理员，展示当前真实配置和可执行修改；专业术语可以存在，但必须与实际配置一致。
- **运行状态**：展示真实探测结果和更新时间；不伪造可用率、延迟趋势或告警历史。

## 6. 全局状态

每个读取数据的页面只实现与该页面真实相关的四类状态：加载、空内容、失败、正常内容。发生用户提交时再
增加提交中和提交失败。状态必须在原任务附近呈现，不能把每种异常都升级为全屏页面或多层确认。

- 加载：保留页面骨架，避免布局跳动。
- 空内容：说明为什么为空，并给一个合理下一步。
- 失败：用普通语言说明，并给重试或返回。
- 离线：只在会影响当前动作时显示。
- 成功：结果已在页面中明显变化时，不再重复弹出长提示。

## 7. 文案规则

### 使用

- “继续上次对话”“全部会话”“正在回复…”“没发出去，点此重试”。
- “身份验证器”“验证码”“恢复码”“等待审核”。
- 动词开头的按钮：“继续”“发送”“通过审核”“保存并返回”。

### 禁止出现在消费者页面

- Provider、Route、Token、Prompt、SSE、Runtime、Policy、Risk、Trace、Memory Lifecycle。
- 模型真实名称、内部 ID、状态码、异常堆栈、数据库字段名。
- “操作失败”“参数异常”这类没有下一步的空泛提示。
- 用英文图标名、图标字体连字或只有工程人员能理解的缩写充当界面内容。

## 8. 跨端边界

- 消费者端以 uni-app Vue 3 同时服务 H5，并为以后生成微信小程序保留兼容结构。
- 平台差异只放在实际需要的适配层，例如登录能力、网络流式实现和安全区读取。
- 管理后台路由、样式和依赖必须在 `mp-weixin` 编译时排除。
- 不为尚未发生的平台差异预建多层抽象；出现真实差异时再加入最小适配。

## 9. 页面验收

一个页面只有同时满足以下条件才算完成：

- 用户在 5 秒内能说出页面用途和主要动作。
- 没有新增产品范围、假数据、专业术语或历史页面入口。
- 加载、空内容、失败和正常内容均有清楚结果。
- 320px 至 430px 移动宽度不横向滚动，中文不出现逐字竖排。
- 底部导航、聊天输入区、系统安全区和键盘互不遮挡。
- 触摸目标、键盘焦点、语义标签和错误提示可用。
- 视觉实现与 `frontend/DESIGN.md` 及已验收 Stitch 代表图一致。
