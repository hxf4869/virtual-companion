# 成年核验与申诉处置（S0-12）

> 状态：本地技术闭环已具备；真实供应商仍默认关闭。本文不是启用批准。

## 1. 当前边界

- 默认 `VC_AGE_PROVIDER_ENABLED=false`，运行时继续使用 `SimulatedAgeVerifier`。
- 只有供应商、区域、数据处理条款、PIA、费用和 Owner 均批准后，才可在私有部署配置启用真实 Adapter。
- 公开注册仍禁止；成年核验通过不等于 ReleaseGate、同意、服务时段或容量门禁通过。
- Runtime 不接收、不保存也不返回证件、证件图片、自拍视频或生物特征。

## 2. 最小化供应商契约

启用后，Runtime 只向批准的 HTTPS host 发送：

```json
{"subject":"age_<HMAC-SHA256 pseudonym>"}
```

`subject` 由部署专用 `VC_AGE_PROVIDER_SUBJECT_SECRET`（至少 32 字节）和内部 owner id 派生；不发送 owner id、用户名、联系方式或对话内容。该 Secret 不得与 API key、JWT 或 owner-binding Secret 复用。

供应商响应必须严格只有以下三个字段：

```json
{
  "state": "ADULT_VERIFIED",
  "ageBand": "18_PLUS",
  "providerVersion": "immutable-revision"
}
```

允许的成对结果仅为：

- `ADULT_VERIFIED` + `18_PLUS`
- `MINOR_VERIFIED` + `UNDER_18`

未知字段、模糊结果、state/ageBand 冲突、版本漂移、非 2xx、DNS/egress 拒绝或超时全部 fail-closed，且供应商失败发生在任何年龄状态写入之前。日志仅记录部署别名、immutable version、延迟和固定 outcome，不记录 subject 或响应正文。

## 3. 私有部署变量

```dotenv
VC_AGE_PROVIDER_ENABLED=false
VC_AGE_PROVIDER_ENDPOINT=
VC_AGE_PROVIDER_REF=
VC_AGE_PROVIDER_VERSION=
VC_AGE_PROVIDER_ALLOWED_HOSTS=
VC_AGE_PROVIDER_API_KEY=
VC_AGE_PROVIDER_SUBJECT_SECRET=
```

- endpoint host 必须同时通过静态 allowlist 和 DNS 公网地址检查。
- `VC_AGE_PROVIDER_VERSION` 必须是供应商不可变协议/模型 revision，不得使用 `latest`。
- 真实值只允许 Secret 管理或私有 `.env` 注入，禁止提交仓库。

## 4. 人工申诉处置

用户仍通过 `/api/v1/age/appeal` 提交 intake；提交后有效状态为 `AGE_APPEAL_PENDING`。人工处置使用：

`POST /api/v1/auth/admin/age-appeals/{appealId}/resolve`

SQL `vc.resolve_age_appeal` 会再次校验 actor 为 ACTIVE `ADMIN` 或 `PRIVACY_OPERATOR`，并原子完成申诉、年龄历史和关联 OpsCase 更新：

| 决定 | 新有效状态 |
|---|---|
| `APPROVE_ADULT` | `ADULT_VERIFIED` |
| `DENY_MINOR` | `MINOR_VERIFIED` |
| `REVERIFY` | `AGE_REVERIFY_REQUIRED` |
| `SUSPEND` | `AGE_ACCESS_SUSPENDED` |

每次成功处置记录固定 decision、1–240 字符人工理由、actor account id 和时间；年龄状态以新历史行追加，provider reference 固定为 `operator-appeal-review`。重复处置、自由文本 decision、非授权角色和直接表 UPDATE 均拒绝。接口响应不返回 owner id、内部备注、证件或生物信息。

## 5. 启用前外部门槛

以下任一项未完成时，必须保持 `VC_AGE_PROVIDER_ENABLED=false`：

1. 供应商、处理区域、DPA/跨境边界、删除/保留期和 PIA 正式批准；
2. immutable provider version、允许 host、费用上限和故障 SLA 已冻结；
3. API key 与 pseudonym Secret 已通过 Secret 管理注入并有轮换方案；
4. ADMIN/PRIVACY_OPERATOR 实际人员、MFA/step-up、主备班表和升级链已确认；
5. 使用合成账号完成 adult/minor/冲突/超时/申诉四类演练，并由 Owner 签署结果；
6. ReleaseGate、真实用户范围和公开注册仍按独立门禁审批。
