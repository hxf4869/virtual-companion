# 09 · 静态加密与密钥治理（CRYPTO-REST）

对应需求 §16.5「数据加密分级·存储」、§17.4、TODO R48。**状态：聊天正文、高敏记忆摘要与会话摘要均已实现；生产密钥治理仍需 Owner。**

## 1. 已实现：聊天正文应用层加密

- **算法与形态**：AES-256-GCM（96 位随机 IV + 128 位 tag）。写入形态（S0-17-B）
  `enc2:<keyId>:<keyVersion>:<base64(iv||ciphertext+tag)>`；读取 dual-read
  `enc2` 当前/上一把钥匙与历史 `enc1:`。算法与 V65 紧急联系人同一方案
  （`RestFieldCipher`，泛化实现）。`conversation_summary.summary` 同样仅写
  `enc2`、dual-read，并由 V79 keyset backfill 处理存量明文/enc1/旧 enc2（S0-32）；
  API/模型边界才解密。
- **边界**：加密/解密都在应用层（写入点 `GenerationReceiveService` 用户消息、
  `GenerationFinalizeService` 助手消息与 ZERO_LLM 回复；读取点
  `MessageHistoryService` 列表/导出/记忆提取等全部经此网关）。SQL 只搬运
  不透明字符串。V108 撤销旧 `record_conversation_summary` 的 runtime 权限并删除
  SQL plaintext `record_turn_summary`；新 metadata 函数只返回 conversation/message ID、
  count 与 service class，Java 先加密再调用 enc2-only wrapper。
- **向后兼容**：`decrypt` 对不带 `enc1:`/`enc2:` 前缀的存量明文**直通返回**；
  checkpoint `reencrypt` 把明文/`enc1`/旧 `enc2` 写成当前 write key（V78）。

## 2. 密钥治理

- 配置：`virtual-companion.crypto.rest-key`（env `VC_CRYPTO_REST_KEY`，
  32 字节 base64）以及 `rest-key-id` / `rest-key-version`（默认 `default`/1）。
  轮换时注入 `VC_CRYPTO_PREVIOUS_REST_KEY`（及 id/version）做 dual-read。
  **密钥只走部署注入，绝不入仓库/数据库/日志。**
- 开发默认键仅限本地与 CI；**production profile 检测到开发默认键即启动
  失败**（fail-closed，与 Auth/datasource 双开关同一守卫）。
- 密钥与数据分离：换钥 = 解密重加密迁移（回填 runner 同机制）。

## 3. 存量数据回填

- V78/V79 提供 message 与 conversation_summary 的 stale-cipher keyset 扫描 +
  条件更新：只返回尚非当前 prefix 的行，更新时再次比较，重跑/并发均幂等。
- 流程：部署注入当前及必要 previous key → 一次启动设置
  `VC_CRYPTO_BACKFILL_ENABLED=true` → runner 分批（500/批）先正文后会话摘要重加密
  → 核对数据库/备份中的有效行全为当前 `enc2` → 关闭开关。中断后从头重跑会自动跳过
  已转换行，不会回写明文；日志只含函数名、数量和数值 checkpoint ID，不含内容。

## 4a. 会话摘要删除与恢复边界（S0-32）

- 普通 turn 只通过 V108 metadata → Java AES-GCM → enc2-only wrapper 写入；无助手消息
  或 incognito conversation 返回空 metadata，因此不产生摘要。
- 单条消息删除在同一事务删除覆盖该 message range 的所有派生摘要，并先断开仍存链指针；
  conversation 删除、清空聊天与账号注销继续由 conversation FK `ON DELETE CASCADE` 清除。
  V108 升级时也清理旧 `valid=false` 摘要，用户删除不再保留摘要 ciphertext 审计副本。
- 恢复/PITR 后先在隔离环境执行 stale-cipher scan；有效摘要若存在非当前 prefix，
  保持 runtime 隔离并用 previous key 重加密；不得在缺 previous key 时把密文当明文覆盖。
  备份只携带 ciphertext，密钥仍在备份边界外；KMS/旧 key 可恢复性演练仍是 Owner 前置。

- **流式片段**（`realtime_event.payload`）保持明文，由 STREAM_FRAGMENT
  保留策略（30 天）治理；如需加密另行评估 seq/gap 兼容性。
