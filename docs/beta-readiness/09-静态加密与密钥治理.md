# 09 · 静态加密与密钥治理（CRYPTO-REST）

对应需求 §16.5「数据加密分级·存储」、§17.4、TODO R48。**状态：聊天正文与高敏记忆摘要均已实现。**

## 1. 已实现：聊天正文应用层加密

- **算法与形态**：AES-256-GCM（96 位随机 IV + 128 位 tag）。写入形态（S0-17-B）
  `enc2:<keyId>:<keyVersion>:<base64(iv||ciphertext+tag)>`；读取 dual-read
  `enc2` 当前/上一把钥匙与历史 `enc1:`。算法与 V65 紧急联系人同一方案
  （`RestFieldCipher`，泛化实现）。`conversation_summary.summary` 同样走
  enc2 写入 / dual-read / V79 checkpoint（S0-32）；API 边界才解密。
- **边界**：加密/解密都在应用层（写入点 `GenerationReceiveService` 用户消息、
  `GenerationFinalizeService` 助手消息与 ZERO_LLM 回复；读取点
  `MessageHistoryService` 列表/导出/记忆提取等全部经此网关）。SQL 只搬运
  不透明字符串——已核实 SQL 从不语义操作正文（`record_turn_summary` 仅
  count 消息）。
- **向后兼容**：`decrypt` 对不带 `enc1:`/`enc2:` 前缀的存量明文**直通返回**；
  checkpoint `reencrypt` 把明文/`enc1`/旧 `enc2` 写成当前 write key（V78）。

## 2. 密钥治理

- 配置：`virtual-companion.crypto.rest-key`（env `VC_CRYPTO_REST_KEY`，
  32 字节 base64）以及 `rest-key-id` / `rest-key-version`（默认 `default`/1）。
  轮换时注入 `VC_CRYPTO_PREVIOUS_REST_KEY`（及 id/version）做 dual-read。
  **密钥只走部署注入，绝不入仓库/数据库/日志。**
- 开发默认键仅限本地与 CI；**production profile 检测到开发默认键即启动
  失败**（fail-closed，与 Auth/datasource 双开关同一守卫）。
- 密钥与数据分离：换钥 = 解密重加密迁移（回填 runner 同机制）。

## 3. 存量数据回填

- V71 提供两个 SECURITY DEFINER 助手：明文批次扫描（keyset）+ 条件更新
  （仅当仍为明文时替换，幂等）。
- 流程：部署注入真实密钥 → 一次启动设置
  `VC_CRYPTO_BACKFILL_ENABLED=true` → runner 分批（500/批）加密全部
  存量正文 → 完成后关闭开关。误二次启动 = 空扫描，无害。
