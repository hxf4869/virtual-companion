# 08 · 数据保留策略（草案 v1）

对应需求 §16.7「数据保留建议」、TODO R48「RETENTION」。**状态：Agent 代拟
草案，Owner/法务复核后生效。** §16.7 明确：具体周期需根据法律、平台和业务
确认；工程上只保证每类数据的周期在 `vc.data_retention_policy` 中**版本化**
（V70），运行时永远从表里读有效策略，不允许开发人员写死。

## 1. 机制（已实现）

- **策略表** `vc.data_retention_policy`：追加式版本（policy_version × category
  唯一），清理路径只读「该类别最新 ACTIVE 版本」；未知/停用类别 fail-closed。
- **分类清理**：V70 为每类提供 age-only 的 SECURITY DEFINER 清理函数；
  调度器每日一次（默认 03:47，可配）逐类执行。单类失败发 P1 告警
  （`RETENTION_PURGE_FAILED`）且不阻断其他类别。
- **开关**：`virtual-companion.retention.enabled`（env
  `VC_RETENTION_PURGE_ENABLED`）默认 **false**——v1 周期是草案，部署在
  Owner/法务复核确认前不得对真实数据启用自动清理。

## 2. 草案 v1 周期（待复核）

| 类别 | 覆盖存储 | 草案周期 | 说明 |
|---|---|---|---|
| NORMAL_CHAT | `vc.message`（含摘要失效联动） | 365 天 | 清理同事务内把覆盖被删消息的会话摘要置 invalid（FR-CHAT-004 规则的集合化） |
| DELETED_CHAT | —— | 30 天 | 当前删除即物理级联，无残留可清；策略行先行占位，函数恒返 0 |
| MEMORY_CANDIDATE | `memory_item` status=PENDING_CONFIRMATION | 90 天 | 仅未确认候选；证据与向量随行级联 |
| REJECTED_CANDIDATE | `memory_item` status=REJECTED | 30 天 | 同上 |
| MODEL_CALL_DETAIL | `provider_attempt` + `generation_route` | 180 天 | 模型调用明细与路由记录 |
| SAFETY_LOG | `safety_event` | 365 天 | 内容安全日志（无 FK 设计，独立清理） |
| EXPORT_RESIDUE | `export_request` 终态行 | 30 天 | 只清 READY/FAILED/EXPIRED；进行中的 PENDING 永不被清扫 |
| STREAM_FRAGMENT | `realtime_event` | 30 天 | 流式片段/持久事件 |

身份审计日志（identity_auth_event）沿用既有 180 天策略（V22/P2-03），
不在本表重复。备份保留周期归 BACKUP 任务（R47）。

## 3. 变更流程

1. Owner/法务确认新周期后，**追加**新 policy_version 行（不改旧行）；
2. 将旧版本行 `active=false`（或直接以更高版本号覆盖读取语义——读取只取
   最高 ACTIVE 版本）；
3. 无需改代码、无需停机：下一次调度即按新周期执行。
