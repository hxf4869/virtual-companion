# 11 · B1 测量与对账（B1-SURVEY / B1-COST）

**状态：采集入口与对账工具已实现；n≥200 的实际数据随受控 Beta 运行期积累。**

## 1. B1-SURVEY 被理解感评分（§26.5）

- **入口**：账号页「本期体验评分」卡片，1–5 分，每天一次
  （`POST /api/v1/survey`；当日重复提交 accepted=false）。
- **存储**：V72 `vc.survey_response`（FORCE RLS owner_isolation；每 owner 每
  日一行；Asia/Shanghai 日界）。无 admin HTTP 读取——Beta 门槛离线计算。
- **指标口径**：n≥200 个独立评分用户、平均分对照 §26.5 五项产品门槛；
  统计由 B1 报告流程在导出数据上完成。

## 2. B1-COST 单位成本对账（§25.9 / §22.19）

现有 admin_usage_summary 是**模拟口径**；真实账单对账走：

```bash
# 1) 导出已结算用量（按日）
docker exec -i <db容器> psql -U postgres -d vc -T \
  < infra/db/measure/export-usage.sql > usage.tsv

# 2) 与供应商账单 TSV（date, cost_usd）对账,默认容差 5%
python3 scripts/measure/cost_reconciliation.py \
    --usage usage.tsv --bill provider-bill.tsv --tolerance 0.05
```

任一日漂移超容差 → `RECONCILIATION FAIL`（退出码 1）——模拟结算成本
(actual_cost 当前恒 0) 与真实账单的差值即「模拟口径缺口」，Beta 期接真实
provider 后该工具即为月度对账入口。
