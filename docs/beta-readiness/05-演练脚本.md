# B0-05 演练脚本：高风险事件演练 + 供应商故障演练（§24.6）

> 状态：Agent 起草稿（2026-08-19）。§24.6 要求 Beta 前完成「一次高风险演练
> 和一次供应商故障演练」。演练在本地/预发环境执行，使用测试账号与 Fake/
> Failure Adapter；**不得用真实用户数据演练**。
> ⚠️ 人工项：演练执行人、观察员、实际执行记录与证据归档
> （`docs/beta-readiness/records/`）由 Owner 组织。

## 1. 演练一：高风险事件（R4_IMMINENT 端到端）

**目标**：验证确定性拦截、人工队列、SLA 时限、升级路径、决定记录全链路。

**准备**：测试账号 A（成年核验通过、已建角色）；值守双人在位（主/替补）；
计时员 1 名；管理端登录就绪。

| 步骤 | 动作 | 期望（通过标准） | 记录 |
|---|---|---|---|
| 1 | 账号 A 在聊天中发送明确自伤危机短语（取 DeterministicSafetyClassifier 测试集样句） | ≤2 秒收到确定性安全提示（含现实求助指引），**无角色化回复**；turn 终态 INPUT_BLOCKED | 截图/事件时间 |
| 2 | 值守人打开 admin 页安全事件队列 | 出现 R4_IMMINENT 行（stage/rule id；无聊天原文） | 队列截图 |
| 3 | 主责模拟不可达（不响应） | ≤5 分钟升级替补；计时从队列行出现起算 | 升级时间 |
| 4 | 替补形成「不联络」决定并记录 | ≤15 分钟内（自事件出现起算）完成决定 | Case 台账 |
| 5 | 复盘核验：safety_event 行、审计、台账三者一致 | 一致 | 复盘记录 |
| 6 | （可选加练）账号 A 配置 VERIFIED 紧急联系人，重复 1-4 但决定为「联络」：执行人按 B0-02 §2 人工联络测试联系人并记录 | 全流程留痕、联系人回复未入记忆 | 台账 + 记忆页核验 |

**失败判定**：任一时限超出 §20.13 上限；出现角色化危机回复；
队列缺失事件行；决定未记录。

## 2. 演练二：供应商故障切换（DEGRADED_AI / ZERO_LLM）

**目标**：验证主模型不可用时三态降级、用户透明告知与数据一致性（§12.10、FR-RES-002/005）。

**准备**：测试账号 B（PREMIUM 分配）；启用真实/本地 provider 的部署配置；
可随时重启 runtime 的预发环境。

| 步骤 | 动作 | 期望 | 记录 |
|---|---|---|---|
| 1 | 正常态基线：发送一条消息 | 正常回复；`GET /service-mode` = FULL_AI | 截图 |
| 2 | 将主 provider 配置 `degraded=true` 并重启 | `GET /service-mode` = DEGRADED_AI（文案「以较低服务等级运行」）；页面/边界台展示降级提示 | 截图 |
| 3 | 账号 B 发送消息 | 生成成功但按 ECONOMY 实际档执行；权益快照 entitled=PREMIUM/actual=ECONOMY 成对留痕；**PREMIUM 已验证摘要不被低质覆盖**（V63 底线） | DB 抽查 |
| 4 | 停用全部 provider（ZERO_LLM） | 生成走确定性兜底回复；不更新会话摘要（FR-RES-002）；`service-mode` = ZERO_LLM | 截图 |
| 5 | 恢复配置重启 | 回 FULL_AI；降级期间消息/记忆/权益账本无缺失；配额对账（`GET /auth/admin/quota-reconciliation`）三类异常均为 0 | 对账截图 |
| 6 | 演练中触发一次举报 + 一次导出 | 时段外/降级下数据权利仍可用 | 结果记录 |

**失败判定**：降级期间应得/实际未成对留痕；低质摘要覆盖高质；
service-mode 展示与实际不符；对账出现异常非 0 且无解释。

## 3. 演练三（建议加练）：数据权利失败恢复

| 步骤 | 动作 | 期望 |
|---|---|---|
| 1 | 人为使导出任务失败（Failure Adapter/中断） | admin 导出队列出现 FAILED |
| 2 | 值守人按 B0-01 §6 处置 | ≤30 分钟确认；24 小时内重跑成功或人工交付 |
| 3 | 注销一个测试账号再尝试登录/刷新 | 立即失效（墓碑生效）；数据删除且合规日志留存 |

## 4. 记录与归档要求

每次演练留存：脚本版本、日期、参与人、每步计时、截图/DB 抽查证据、
发现的问题与整改项、复练计划。归档于 `docs/beta-readiness/records/`，
作为 §24.6 门禁「一次高风险演练和一次供应商故障演练」的签署证据。
