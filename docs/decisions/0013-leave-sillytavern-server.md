# ADR-0013：迁出 SillyTavern 服务端，保留浏览器引擎与角色卡兼容

- 状态：**Proposed**
- 日期：2026-11-06
- 决策人：Owner；本稿由服务端架构负责人整理，待总调度审阅
- 代码基线：`ecac91ad1864c17de759484203327755ac41ee90`
- 实施草案：[ST 退出计划、接口盘点与离线测量](../planning/2026-11-06-st-exit-plan.md)
- 关联：[ADR-0009](0009-v2-sillytavern-host-direction.md)、[ADR-0011](0011-mobile-uniapp-ui-st-engine.md)、[ADR-0012](0012-mobile-react-shared-engine.md)

Owner 已于 2026-11-06 决定服务端全部迁出 ST，最终停止 ST Node 与 ST 核心补丁；浏览器独立引擎、Tavern Helper / EJS / MVU、JSONL 聊天及 PNG 角色卡兼容保留。先确定聊天存储与分页历史接口，再让手机 MB2-6、服务端迁移、聊天记忆优化三线并行。本 ADR 的 Proposed 表示分期、契约细节及切换门槛尚待审阅，不重新打开上述方向选择。

## 1. 背景：目前 ST Node 实际承担什么

桌面已由 React 独立启动；ADR-0012 也让手机共用独立浏览器引擎。移除完整 ST 页面没有移除服务端依赖。当前职责如下，逐接口、调用方行号与补丁证据见计划 §2、§3。

| 领域 | ST / server-plugin 当前职责 | 已在浏览器或 Go 的职责 |
|---|---|---|
| 聊天 | JSONL 全量读取与保存、会话列表、导入导出、改名、删除、群聊与分支；F2 原子 CAS、稳定身份、墓碑及中断恢复 | 浏览器 Session 管理编辑、swipe、MVU、生成生命周期；Go `conversation` 绑定及 `st_message_source` 为核验镜像 |
| 卡片与配置 | PNG/JSON/CHARX 导入、卡片字段、世界书 JSON、预设与 settings.json、人设头像、背景、图片、附件、缩略图；部分配置按旧值条件提交 | 浏览器组装提示词、世界书扫描、宏、正则、Slash、Helper/EJS/MVU 与卡片 iframe |
| 生成 | `/api/backends/chat-completions/generate`、协议转换与 SSE、停止、tokenizer 与 bias；插件解析用途绑定、取密、预算/记忆/剧情最终校验、工具循环及用量结算；拒绝旁路生成 | Go 是模型目录、凭据、用途、预算、工具与剧情权威；浏览器发起唯一前台流程 |
| 身份与入口 | 在静态资源及 API 前向 Go 验证会话；绑定 ST handle；提供 `/auth/`、`/`、`/desktop/`、`/m/`、过渡 `/native/` 与自托管供应商资产；代理 Go API | Go 密码/TOTP、opaque session、权限、RLS、账号删除意图 |
| 来源及权利 | 私有 `/internal/v1/st/{sources,inbox,data/export,data/delete}`：持久来源读回、后台 inbox 写入、导出与删号；用户目录与账号映射登记 | Go 记忆来源核验、遗忘/删除屏障、任务、主动消息、关系、语音及对象存储；MemoryCore 提取、检索与派生 |

`session.js` 保存整份 `chat`，`f2-logic.js` 克隆并多次 JSON 编解码；`f2-store.js` 又完整读取旧聊天、比较来源、序列化 JSONL、fsync、rename。一次单消息编辑也随全部历史增长。阶段 0 的合成样本中，20,000 条约 50.38 MiB，一次直接调用 F2 的保存流水线 P50 为 5.16 秒；这还没有 HTTP、浏览器渲染、真实数据库或模型耗时。

数量须按代码纠正：本提交 `scripts/lib/paths.mjs:53` 的 `CORE_PATCH_SPECS` **24 项**；`patches/` 顶层 **28 个 JSON**，另外 4 个是 Helper/EJS/MVU 资产规格。没有找到第 29、30 个顶层规格。“停掉 30 个核心补丁”按停止全部 ST 服务端及原生页面核心补丁的目标执行，不虚构两个补丁，也不因此删除保留引擎必需的资产适配。MemoryCore 的独立补丁集不在此计数内。

## 2. 决策

1. **Go 接管服务端权威与公开同源 API。** 目标为 Go + PostgreSQL + blobstore，反向代理提供现有同源入口与构建产物。ST Node、ST 用户目录在线写入、server-plugin 运行时及其核心补丁最终退出。MemoryCore 是既有独立服务，本决策不要求移植它，也不等于消灭所有 Node 构建工具或进程。
2. **浏览器仍运行唯一共享引擎。** 继续使用独立 Session、提示词计算和脚本卡运行模块。前台一轮输入只有一个生成流程；迁移的是生成服务端代理，不在 Go 再组装一份竞争的浏览器提示词流程。普通前台、Helper/EJS 嵌套生成、MVU、严格剧情使用同一受控入口和生命周期。
3. **聊天先行。** 按消息/候选存储，使用稳定 ID、游标、操作幂等和细粒度前置条件，替代每次整文件 F2 CAS。不同消息追加、无关字段编辑自动串行提交或安全重放；同一文本、同一候选、MVU/剧情状态的真实语义冲突不做静默覆盖。保留来源守卫和用户草稿。
4. **单一写入权威。** 每个迁移范围同时只有 ST 或 Go 一个写入者；切换由持久 authority epoch 与写入门禁控制。不双写 JSONL 和数据库，不用异步双写作为回滚保证。JSONL/PNG 是交换、备份和回退格式，不是 Go 在线聊天的第二份真源。
5. **保留数据与兼容，不扩大产品范围。** 迁移全部现有 V2 数据。ADR-0009 E3 仅处理 V2 前旧数据，不授权清理现在的聊天。暂时保留 ST 路径兼容适配器，并给每条路径明确退出阶段；任意第三方插件的任意 HTTP/文件访问不自动获得兼容承诺。
6. **先审契约，再并行实现。** 计划中的 OpenAPI 只是文档草案。本轮不修改 `specs/`、TODO、Backlog 或产品代码，不启动服务，不碰开发/生产数据库，不提交/推送。接受本稿也不自动授权实际数据切换、部署或真实模型调用。

## 3. 分阶段、退出条件与回滚

每阶段退出都要求对应离线测试和后续获准的合成受管验证完成；以下门槛不是本轮运行结果。

| 阶段 | 交付与退出条件 | 回滚与停止点 |
|---|---|---|
| **0 测量与契约** | 完成接口/供应商间接调用/补丁清单、四档合成测量；确定分页、操作、来源身份和脚本完整历史兼容边界；Owner 确认计划 §7 待决项，三线共享契约版本 | 只有文档和临时合成文件，可撤回草案；不得借测量读真实聊天。数量差异和性能边界明确留档 |
| **1 聊天存储与分页** | Go 会话/消息/候选/元数据及导入导出；双向分页；幂等、并发、分支、inbox、来源与删除屏障；Session 适配；50 条显示页不依赖全量历史；新旧格式往返及中断恢复验证；MB2-6 接入真实分页后单独验收 300ms | 切换前 ST 仍是唯一写者，Go 影子导入只核对。切换后冻结 Go 写入，导出切换以来的完整最新快照及身份/墓碑，恢复到隔离 ST 根并核验，再提高 epoch 切回。不能只把流量指回旧 JSONL；客户端未提交操作继续保留，不能假报已保存 |
| **2 生成代理迁 Go** | 三协议、工具循环、取消/断连、用量一次结算、最终上下文预算、记忆重核、ActorView、凭据隔离、无旁路；tokenizer/bias 替代有差异夹具；ST 生成接口无新流量；同输入不重复生成 | 以单个 generation/run 为界路由；失败切换只影响下一轮。取消或等待旧轮终态，处理 UNKNOWN 用量；不得把可能已发出的请求自动重发。旧插件需要的来源读回接阶段 1 Go 权威适配器 |
| **3 卡片、世界书、预设、设置、图片迁 Go + blobstore** | 配置用版本化 JSON 保留未知字段；卡片原 PNG/资源保存于 blobstore，解析文档关联对象；JSON/PNG/CHARX 既有导入能力、世界书及人设/背景/附件兼容；身份/静态资源/Go 代理替换；导出、删号、备份覆盖所有新域 | 按配置域冻结后导出当前版本和对象映射，核验隔离副本后切回域权威。禁止用旧备份覆盖新字段/对象；丢失未知字段或对象引用时停止。图片上传先暂存、事务引用、失败回收，不能形成无界孤儿 |
| **4 停 ST Node 与核心补丁** | 所有生产及保留脚本路径在 ST 不启动的合成栈中通过；移除 ST 路由/handle/私有通道/运行副本依赖与全部 24 项核心补丁；手机按 ADR-0012 验收并获 Owner 确认后退役 `/native/`；备份恢复演练、最终残留扫描通过 | 保留一套已核验的回退制品与最新加密一致性快照；重启旧程序前必须完成阶段 1/3 反向迁移及删除并集对账。只重启旧 ST 容器不是回滚。破坏性清理放在回滚窗口结束且 Owner 确认之后 |

阶段 1 契约确认后，手机 UI/缓存/虚拟列表、Go 存储迁移、记忆来源适配可以并行。生成迁移和资源迁移也可并行准备，线上权威切换按上述顺序；同一文件只交给一个写入 owner。阶段 4 的必要条件是已不再使用 ST 服务端，不是把原生兼容页面隐藏起来。

## 4. 数据迁移与备份

### 4.1 保留清单和身份

| 现有数据 | 新归属与保留要求 |
|---|---|
| `chats/**/*.jsonl`、`group chats/*.jsonl`、`groups/*.json` | Go 聊天表与消息/候选 JSON；头部、顺序、隐藏消息、swipe、swipe_info、extra、variables、未知扩展字段完整保留；群聊说话者及分支单独映射 |
| `vc_f2.id/revision`、`vc_message_id`、`extra.vc_source`、`vc_branch_root`、`vc_binding`、`.vc-f2` | 可信迁移保留 UUID、source revision/generation、branch root、Go conversation/relationship 绑定和墓碑；文件路径只作别名，不变成主键。同一原始文件多次导入不重复建会话 |
| `characters/*.png` 与卡片 JSON/CHARX 关联资源 | 原二进制逐字节留存并做 SHA256；结构化元数据保留 `chara`/`ccv3` 等块及未知字段，不重编码丢私有块。重复卡不合并稳定 characterRef |
| `worlds/`、各类预设目录、`settings.json`、群组、人设及私有扩展设置 | Go 版本化 JSON 文档；世界书 UID、全局/角色/聊天绑定、正则、脚本开关及脚本内容保留。设置中的供应商凭据不导入浏览器文档，仍由 Go 凭据域管理 |
| `User Avatars/`、背景、`user/images`、`user/files`、其他卡片关联媒体 | blobstore 原对象及内容哈希/类型/大小/归属索引；旧同源 URL 的受鉴权别名；附件和语音引用不得改成公开桶 URL |
| `_vc_accounts`、ST cookie/账号资料、secrets、运行配置 | 私有加密备份保留回退所需部分；在线身份继续由 Go 权威，ST handle 只作迁移对照。凭据迁移由另行授权的私有操作执行，不打印、不进入导出或本次审计 |
| Go `st_message_source`、记忆/摘要、MemoryCore、inbox、语音与删除意图 | 保留现有身份关系和遗忘状态；来源镜像不能代替原聊天（无非选中 swipe 和任意 extra）。备份包含 Go、MemoryCore 与有效媒体，对账完成前关闭记忆提取/检索发布 |

### 4.2 执行顺序

1. 获准操作后，在维护窗口冻结拟迁移账号的聊天写入、生成提交、inbox 投递和来源任务；发放新 epoch，旧客户端写入明确拒绝并保留草稿。等待队列排空。按原规则停止 MemoryCore 后取一致快照。
2. 为文件、对象和数据库写无正文的 manifest：范围、schema 版本、计数、字节数、哈希、原身份到新身份/别名映射、删除屏障高水位。内容留在加密归档内，日志只记汇总；哈希和映射也不进入公开仓库。
3. 复用既有 `backup.sh` / `restore.sh` 的加密、MAC 自校验、空目标与恢复门机制。原脚本依赖 ST 目录，后续 SX-13 扩充为新数据域；在扩充与演练完成前不能声称新栈已备份。
4. 导入**隔离库和隔离桶**，不覆盖现用库；以 `(migrationRun, owner, oldIdentity, sourceHash)` 幂等 checkpoint 恢复。先卡/文档/对象，再聊天/来源引用；损坏行、非法 UTF-8、重复 ID、缺文件、悬空对象进入失败清单，禁止截断或跳过后继续宣告成功。
5. 全量核对会话数、消息/候选数、未知字段、PNG 哈希、世界书绑定、对象引用、分支、来源 revision/generation 与删除状态；合成回归验证编辑/swipe/遗忘/回档/语音访问撤销。可信内部迁移与用户上传 JSONL 是不同通道，上传内容不能决定 Owner、绑定、版本或已有来源身份。
6. 停写期间产生的尾差按最新快照重新核验，迁移权威表一次切换到 Go。先禁止旧 ST 写入口，再开放 Go；旧客户端走兼容适配器或重新加载，不能偷偷继续写旧盘。Go 原消息事务与来源失效屏障必须先于记忆检索恢复。
7. 按阶段退出条件验证。回退时同样冻结、导出最新状态、并入删除清单、核对和切换 epoch；从快照恢复不能复活已遗忘来源、已删账号/聊天或已撤销音频。

### 4.3 保留与清理

沿用 OP-11：成功切换后只保留当前/仍被运行引用的制品、**最新一份已自校验加密备份和本次迁移快照**（归入本次扩展快照，不另起无限版本链）。下一阶段成功核验后替换上一份迁移快照；失败时保留最后可恢复的一套，清理本次未引用暂存对象/临时库/临时目录。创建入口落实数量与容量限制、成功/失败/中断清理；正式保留天数、备份位置和密钥保管由 Owner 决定。

删除清单在归档之外持续有效，恢复使用“当前权威删除 ∪ 最新外部清单 ∪ 当前数据根”的并集。任何来源不可核验时保持恢复门 blocked，不能把不可达当作已删除或已恢复。离线备份清除与在线逻辑删除仍分开描述。所有真实迁移和恢复操作均不在本轮执行。

## 5. 许可与不变边界

迁出 ST Node **不改变仍保留代码的许可**。按仓库现有 ADR-0009 §3 与版本锁：ST 浏览器派生计算代码、自有集成及 EJS 继续按其 AGPL 标识保留源码、修改说明及 notices；Tavern Helper 的 PolyForm Noncommercial 约束继续适用，整个 V2 仍只供 Owner 本人非商业使用，不向他人提供服务。MVU 及 npm/vendor 依赖继续按锁和各自许可登记。

Go 自有独立实现维持现有 Apache-2.0 边界；不能把 AGPL JS 逐行翻译到 Go 后自动当成 Apache。协议移植须记录代码来源，评审复用/派生范围与许可归属；仅删除服务器进程不能证明解除 AGPL 或非商业限制。构建仍发布对应 notices，许可门禁覆盖保留的浏览器派生物和新增 Go/blobstore 依赖。本稿不授权商业化或对外服务。

身份、TOTP、CSRF、同源/Origin、RLS、其他域字段加密、记忆域明文保护、日志不落正文/凭据、语音只经 Go、不开公开注册/支付、真实用户 Beta 门禁均不变。前台生成迁到 Go 后也不顺手改变 ADR-0009 §4 的安全策略产品选择；前台与 Go 自发触达内容仍按既有不同规则处理，不能误套旧 Go 全量生成策略。

## 7. 风险与待确认

- **分页与脚本语义**：`SillyTavern.chat`、Helper 同步整段读取与 MVU 历史重演不能返回残缺数组。先显示末页与“脚本可运行”是两个状态；大卡完整装载可能超手机 15 MB 堆预算和发送就绪预算，需按计划分档验收并由 Owner 处理取舍。
- **来源撤销**：切 swipe、编辑、删除、回档、恢复可能错误复活记忆或语音；必须保留 ID 和 source generation，来源失效与消息事务同步生效。
- **并发语义**：机械减少 409 不等于允许自动合并 MVU 或剧情状态；同字段竞争须留稿并给局部解决方式，不能默默 last-write-wins。
- **迁移双权威**：过渡 ST 导出/私有来源/inbox 也必须指向 Go 权威；只改前台保存接口会留下旁路。
- **协议差异**：tokenizer、Claude thinking、Responses reasoning、工具及取消结算均影响正确性；不能只验证“能生成文本”。
- **资源和许可**：未知卡字段、PNG 块、私有脚本 URL、动态 iframe 资源及源码许可是阶段 3/4 的主要遗漏风险。
- **收益边界**：本次为 4 核合成测量，未测手机、HTTP、真实磁盘冷缓存、PG 或模型 TTFT；迁 Go 不消除浏览器完整脚本历史的 O(n) 成本。

Owner 待决清单与建议见计划 §7：权威切换粒度/窗口、消息存储方案、脚本兼容的大历史性能边界、契约容量/保留参数、备份保管，以及“30”计数差异。服务端退出方向、保留复杂卡、非商业边界和 MB2 的 300ms 目标不在待决列表中。
