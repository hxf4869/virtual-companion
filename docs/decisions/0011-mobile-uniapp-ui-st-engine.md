# ADR-0011：移动端采用独立 uni-app 界面 + 同源 ST 引擎

- 状态：Accepted（规划，实现以 MB-0 验证通过为前提）
- 日期：2026-11-02
- 决策人：Owner
- 替代：ADR-0010（uni-app 壳 + web-view 承载同一 ST Web）
- 关联：ADR-0009（V2 SillyTavern 宿主方向）、`DESIGN.md`、`docs/planning/2026-11-02-session-handoff.md` 第 2 节、
  出图提示词 `docs/product/v2-redesign/mobile/image-prompts.md`

## 背景

Owner 2026-11-02 决定：移动端（H5 + Android + iOS）用 uni-app 独立开发，桌面网页不再兼容手机。
2026-11-03 桌面补充决定：已有 React 电脑端独立启动并替换当前页面，沿用沉浸玻璃（DESIGN.md 第 16 节），
不得运行完整 ST 页面或隐藏宿主。本 ADR 的同源隐藏 ST 引擎仅适用于手机，不授权桌面采用该机制。
手机 `mobile/src/engine/engine.mjs` 目前默认加载 `/`，这是 NF-10 切根前必须适配的真实消费者；
先提供并验证明确的原生宿主入口，再更新手机地址，最后切换桌面默认入口，不重写手机聊天引擎。

约束：聊天提示词在 ST 前端组装，角色卡脚本（Tavern Helper / EJS / MVU）依赖浏览器 DOM；uni-app 原生页面与非 H5
逻辑层无法运行它们。ADR-0009 §2 规定 ST 持有原始聊天、Go 不并行改写 ST 聊天文件、一轮前台输入只有一条生成链（ST）。

候选路线：A 全原生（Go 组装提示词并生成）、B 聊天页 web-view 嵌 ST 手机网页、C 先 A 后补 web-view，以及调研中补出的
D 独立界面 + ST 作引擎。同类开源项目里，纯客户端方案（ChatterUI、MiniTavern）都放弃了脚本卡，套壳方案
（SillyTavern-Android）就是 B。

## Owner 选择（2026-11-02 问答）

| ID | 问题 | 选择 |
|---|---|---|
| M1 | 路线 | **D**：独立 uni-app 手机界面，ST 作同源引擎；手机上保留角色卡脚本与剧情 |
| M2 | 聊天记录 | 手机与桌面同一份，两端可接着聊 |
| M3 | 交付端 | H5 + Android 先，iOS 后（Apple 开发者账号另行决定） |
| M4 | 首版系统能力 | 语音输入、语音朗读回复、后台保持连接、语音通话 + 角色来电、分享给 TA + 通知快捷回复 |
| M5 | 系统推送 | 首版不接系统推送服务，沿用邮箱 + 飞书（D2） |
| M6 | 其他 | 联网搜索与网页读取作为聊天工具，桌面与手机共用，单独立项（backlog `TL-1`），不属于本 ADR |

朋友圈 / 角色动态、一起听歌、桌面小组件、手机状态作主动由头、应用锁与隐私遮罩记入后续候选，不在首版。

## 决策

### 1. 架构：界面与引擎分离

- 手机界面是独立 uni-app 工程（Vue 3，仓库根目录 `mobile/`），按 Apple 应用语法从头设计，不复用 ST 手机布局。
- 同一页面内以**同源隐藏 iframe** 运行一份 ST 宿主（含 Tavern Helper / EJS / MVU 与自有扩展），作为引擎。
  手机界面通过一个引擎适配模块调用 ST 公开前端接口（`getContext()` 的 `chat`、`generate`、`eventSource`、
  `saveChat` 等，自有扩展已在用）完成发送、停止、重新生成、候选切换、编辑、删除与流式显示。
- 结果：提示词组装、世界书、预设、角色卡脚本仍由 ST 执行；**只有一条生成链（ST）与一份聊天文件（ST）**，
  F2 原子版本冲突检查照旧。ADR-0009 §2 不需修订。
- 不改 ST 核心；确需补丁时沿用可重放补丁集规则。适配模块是唯一接触 ST 内部的地方，ST 升级时只核对这一层。

### 2. 富内容与 ST 视图

- 手机原生气泡负责文字、Markdown、图片、表情包、语音条、引用。
- 含角色卡前端（HTML / iframe / 状态栏）的消息、严格剧情舞台、酒馆配置（AI 回复配置、提示词格式、世界书、扩展、
  人设、背景、界面、API 连接、角色卡）切到 **ST 视图**：把同一个引擎 iframe 全屏显示，关闭后回到原生界面。
  不在原生侧复制渲染角色卡内容。
- 消息含卡片前端时，气泡位置显示一行占位，点开进入 ST 视图并定位到该楼层。
- 因此 ST 手机布局不删除，**冻结为 ST 视图的显示层**：只修阻断缺陷，不再做手机体验改版。

### 3. 部署形态

- H5 构建产物由现有入口同源提供（路径如 `/m/`），不新增端口、域名或服务器暴露面；手机浏览器访问根路径时引导到 `/m/`。
- 手机界面只使用浏览器现有的同源路径（与自有扩展相同的管理桥与接口），不直连 Go 内部端口、TTS / ASR。
- 登录沿用现有会话；`/m/` 与 ST 同源，共享 Cookie。

### 4. App 壳（Android 先）

- uni-app App 用 `web-view` 加载 `/m/`；壳只做网页做不到的系统能力：
  - 安全区与状态栏、Android 返回键映射为网页内返回；
  - 麦克风、通知权限；
  - **前台服务保活**：App 在后台时保持网页进程，使流式生成与实时连接不断；
  - **本地通知**：网页通过桥发出通知（含快捷回复输入、来电全屏通知）；回复文字回传网页，由网页经引擎发送；
  - 系统分享入口（「分享给 TA」）：把图片 / 链接 / 文字交给网页的发送面板；
  - 从后台恢复时通知网页刷新状态。
- 壳内不放业务逻辑、不保存第二份业务状态、不直连 Go 或 TTS / ASR。网页进程不在时，通知点击打开 App，不在壳内回复。
- Android 用本地离线打包，不用会上传代码的云打包；iOS 在 Owner 决定开发者账号后另行立项。

### 5. 通知与后台

- 首版不接 APNs、厂商通道、uni-push 或 Web Push。App 存活（前台服务）时用本地通知；被杀后由邮箱 + 飞书兜底，
  D2 规则（默认泛化标题 + 受登录保护链接）不变。
- App 本地通知（Owner 2026-11-02）：解锁后的通知栏默认显示角色名与正文，可快捷回复；锁屏只显示泛化标题
  （Android 锁屏可见性设为隐藏内容）。可在设置 › 通知中关闭正文。backlog `UX-3`（Web Push）不属于移动端首版。
- 生成在客户端引擎中进行。App 在后台依赖前台服务；进程被杀或系统挂起导致回复中断时，回到前台检测未完成回复，
  提示「继续」（ST 续写）。**不在 Go 复制一条生成链**。

### 6. 语音通话与角色来电

- 通话：客户端分段收音 → Go ASR → ST 引擎生成短回复 → Go TTS（低时延引擎优先）→ 播放；用户开口即打断播放并停止生成。
  通话文字写入同一聊天并标明来自通话。每引擎并发 1、不改推理参数（AGENTS.md 语音规则）继续有效。
- 来电：Go 主动引擎新增「来电」触发，开场内容经本地安全策略（ADR-0009 §4）。App 存活时显示来电全屏通知；
  未接则生成语音留言进陪伴收件箱，并按 D2 通知。
- 接口与数据变化按契约先行：先改 OpenAPI / catalog，迁移从当前最大版本顺延。

### 7. 设计

- 手机界面沿用 Apple 应用语法、UX-11「B 沉浸景深」风格与 UX-23 C5 手机聊天参照；先按出图提示词出图，
  Owner 挑选后把图翻译为 DESIGN.md 的手机 token，再开发。DESIGN.md 第 16 节（桌面）不变。
- 对话类页面背景（Owner 2026-11-02）：默认极光；可按角色换成场景图，来源为酒馆已有背景、自己上传；
  自动生成待生图服务（ST-6）定下后再加。场景图统一加模糊与上下渐隐。

### 7.1 主题扩展点（Owner 2026-11-02）

首版只交付一个默认主题，但从工程骨架起预留主题切换，以后加主题只新增主题文件，不改页面代码。

- **主题能改什么**：颜色、材质、圆角、字体、背景、动效，以及组件的预定义变体（气泡形状、标签栏样式、
  图标风格、提示音）。布局、交互、文案不随主题变。每个主题都有浅色、深色两种模式；角色氛围色是主题的输入。
- **实现约束**：页面与组件只引用语义 token，不写字面值（DESIGN.md §3.1）；组件变体是组件内定义的有限枚举，
  主题只选择变体、不注入样式代码；主题是一份数据文件，注册表只列出主题。
- **生效范围**：设置 › 外观选全局主题；每个角色可单独指定主题，进入该角色的对话时切换。
- **存储**：存服务器，多端同步；桌面以后做主题时复用同一设置。接口与存储按契约先行，具体落点在 MB-2 定。

### 8. 范围与授权

- 移动端条目按 V2 工作项处理（Owner 2026-11-02 确认），编号 `MB-*`，记入 handoff backlog；依赖按 ADR-0009 §3 的条件引入
  （许可允许非商业自用、版本固定、登记许可清单）。uni-app 框架与 Android 构建工具属于此类。
- ADR-0009 §3、§4 继续有效：仅 Owner 本人非商业使用，不向他人提供服务。
- 本 ADR 不授权：iOS 证书 / 开发者账号 / 上架、任何费用、系统推送服务、云打包、部署（部署仍按 AGENTS.md 发布规则另行指示）。

## 实施顺序

1. **MB-0 可行性验证**（下节清单），不写产品界面。
2. MB-1 出图与选图 → DESIGN.md 手机 token。
3. MB-2 起：工程骨架与引擎适配 → 聊天 → 其余一级页面 → Android 壳 → 语音输入 / 朗读 → 通话与来电 → 分享与快捷回复。
   具体拆分在选图后写入 backlog。

## MB-0 必须验证（本 ADR 不声称已通过）

- 引擎冷启动到可发送的时长（桌面实测宿主初始化约 15.7s），以及启动期间先显示会话列表与历史的方案；
- 低端 Android web-view 下同时运行界面与隐藏 ST 的内存与流畅度；
- `getContext()` 等公开接口能覆盖发送、停止、重新生成、候选切换、编辑、删除、流式事件，且不需改 ST 核心；
- 隐藏 iframe 中 Tavern Helper / EJS / MVU 与卡片脚本正常运行，切到 ST 视图后状态一致；
- App web-view 中登录 Cookie 保持、`getUserMedia` 麦克风权限、软键盘避让、返回键；
- 前台服务保活下后台 30 分钟流式与实时连接不断；本地通知快捷回复回传；系统分享入口。

验证环境（Owner 2026-11-02）：用本机 MuMu 模拟器 + adb 完成；后台以 adb 强制 Doze 模拟锁屏放置。模拟器测不准的两项——厂商杀后台策略、真实性能与内存压力——在报告中标「待真机」，于 MB-6 真机走查确认。

任何一项不通过，先回到本 ADR 修订，不在壳里补业务逻辑，也不在 Go 复制生成链。

## 后果

- ADR-0010 被替代；DESIGN.md 第 15 节改为引用本 ADR，手机规范在 MB-1 重写。
- 聊天有两个界面（原生气泡与 ST 视图），但数据与生成链只有一套。
- 新增顶层目录 `mobile/`，需纳入许可门禁与 `scripts/check.sh` 的对应检查（MB-2 时落实）。
