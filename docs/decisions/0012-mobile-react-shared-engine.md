# ADR-0012：手机端改为与电脑端共用 React 代码与独立引擎，Capacitor 打包安卓与 iOS

- 状态：Accepted（Owner 2026-11-06 问答确认）
- 日期：2026-11-06
- 决策人：Owner
- 替代：ADR-0011 第 1、2 节（uni-app 界面 + 同源隐藏 ST 引擎、ST 视图）、第 4 节中“uni-app App 用 web-view”的壳选型，
  以及第 8 节“iOS 另行立项”
- 保留：ADR-0011 第 3 节（`/m/` 同源入口、不新增暴露面）、第 5 节（通知与后台，不接推送服务）、第 6 节（语音通话与来电）、
  第 7、7.1 节（设计与主题扩展点）、第 8 节其余范围与授权
- 关联：ADR-0009、DR2 电脑端重建、实施计划 `docs/planning/2026-11-06-mobile-react-rebuild-plan.md`

## 背景

ADR-0011 的路线 D（独立 uni-app 界面 + 同源隐藏 ST 引擎）在 `mb-mobile` 上完成了 MB-0–MB-5、MB-7–MB-10 的 H5 部分，
MB-6 Android 壳未实施，分支未合并。按 ADR-0011 第 4 节，uni-app 在 App 中也只是用 `web-view` 加载 `/m/`，
界面始终是网页，uni-app 的原生多端渲染并未使用。

电脑端于 2026-11-06 完成 DR2 并合入 main（`f502c4b9`）：单一 React 应用，不运行完整或隐藏的 ST 页面；
聊天、复杂卡（Tavern Helper / EJS / MVU）、提示词组装与 Slash 由 `extension/vc-model-settings/desktop/standalone/` 的独立引擎执行；
已有四档布局、主题与角色覆盖，以及手机端没有的大量页面。

本项目有一个决定性约束：引擎与角色卡脚本依赖浏览器 DOM，任何技术路线的 App 都必须包含 WebView 运行引擎与卡片。
在此约束下比较了 React + Capacitor、React Native、Flutter / 原生与继续 uni-app（计划第 0 节），
React Native 与 Flutter 仍需把引擎放进隐藏 WebView 并跨桥调用，且无法复用电脑端界面。

## 决策

1. **一套 React 代码，两个入口。** 手机界面在 `desktop-ui` 工程内新增手机入口与手机壳，与电脑端共用数据层、会话桥、
   设计 token、基础组件和各功能的业务逻辑。`/m/` 提供手机构建产物，`/` 与 `/desktop/` 仍是电脑端。
2. **一个引擎。** 手机直接使用电脑端的独立引擎与卡片运行模块，不加载隐藏 ST 页面，不再有“ST 视图”。
   复杂卡在消息内或全屏卡片页中渲染；剧情与酒馆配置使用 React 页面的手机布局。
3. **Capacitor 打包安卓与 iOS，同时交付。** 壳加载同源 `/m/`，只做网页做不到的系统能力（ADR-0011 第 4 节边界不变）。
   安卓本机离线构建 APK 自行安装；iOS 用 Owner 的付费 Apple 开发者账号在 Mac + Xcode 本地构建。
   不上架应用商店、不用云打包，签名材料不入库。
4. **性能是验收门槛。** 预算见计划第 3.6 节（Owner 选择更严格档）。MB2-1 实测达不到时先报告 Owner；
   若 WebView 方案无法达标，可只把会话列表与对话页改为 React Native，其余代码不变（业务逻辑因此必须与框架解耦）。
5. **优先复用成熟组件。** 手机壳、页面栈与侧滑返回、底部弹层、左滑操作、长列表虚拟化、安全区与键盘避让一律使用成熟开源组件，
   不自行实现。Ionic React 与“Base UI + vaul + motion + react-virtuoso”两套方案在 MB2-1 中对比后选定。
6. **iOS 首版不接推送服务。** 因此 iOS 上：App 在后台约 30 秒后流式生成会被挂起，回到前台提示“继续”；
   来电只在 App 打开时显示全屏来电页，后台时为普通本地通知并留未接留言；邮箱 + 飞书兜底不变。
   安卓按 ADR-0011 第 4、5 节做前台服务保活与全屏来电通知。
7. **设备范围。** 手机竖屏（320–430）与横屏、折叠屏与小平板（600–900，手机布局双栏变体）使用手机界面；
   iPad 与大平板在 App 中加载电脑端布局。
8. **入口。** 手机浏览器打开 `/` 不自动跳转，电脑端窄窗显示“打开手机版”入口。
9. **设计严格按图。** MB-1 未覆盖的页面由执行者出图，Claude 审核后交 Owner 选定；实现与验收以选定图为准。
10. **`/native/` 移除。** 手机版验收通过并经 Owner 确认后，移除 `/native/` 原生手机宿主与旧手机外壳，只保留一个引擎。
11. **uni-app 不再使用。** `mb-mobile` 的 Vue 代码不合并，只作功能与交互参考；其后端与契约改动单独迁移到 main。

## 后果

- 新功能只写一次，四个端（电脑网页、手机网页、安卓、iOS）共用一份聊天与一条生成链（ADR-0009 §2 不变）。
- 手机首屏需单独治理：电脑端最大三个 JS 包合计约 2.3 MB（gzip），手机入口必须按路由拆分并延迟加载引擎。
- DESIGN.md 第 17 节改为“手机界面”（不限定 uni-app），数值沿用；ST 视图相关描述随实现修订。
- 新增依赖（Capacitor 及插件、手机组件库、Android / iOS 构建工具）按 ADR-0009 §3 的条件引入并登记许可清单。
- iOS 体验受系统限制，与安卓存在已知差异（第 6 点），在设置与帮助文案中如实说明。

## 不授权

上架应用商店、系统推送服务（含 APNs / VoIP 推送）、云打包、部署；Apple 账号费用由 Owner 自理。
合并 main 与部署仍按 AGENTS.md 另行指示。
