# Virtual Companion 前端重做实施计划

> 日期：2026-09-01
> 状态：实施基线；默认陪伴关系已确认，未来成年准入延期决定，见第 10 节
> 性质：产品级重做，不是旧页面换肤或兼容性重构
> 范围：消费者 H5、未来微信小程序可复用结构、H5 管理后台，以及完成这些页面所必需的后端契约

## 1. 计划权威与交付目标

实施时按以下顺序处理冲突：

1. 产品目的、上线范围与禁止项：[`PRODUCT.md`](../../PRODUCT.md)。
2. 页面职责、流程、状态与文案：[`docs/product/frontend-redesign.md`](../product/frontend-redesign.md)。
3. 视觉令牌、组件、布局与 AI 开发规则：[`frontend/DESIGN.md`](../../frontend/DESIGN.md)。
4. 已验收构图参考：[`docs/design/stitch-reference.md`](../design/stitch-reference.md)。
5. 本文只定义实施顺序、契约依赖、切换方式和验收门槛，不改变上述产品决定。

本文取代 `2026-08-29-frontend-simplification-redesign.md`。旧页面、旧测试和历史规划只能帮助确认
已有接口，不再拥有页面结构、文案、路由或视觉决定权。

完成态必须同时满足：

- 未登录用户能完成“账号 + 密码 → 身份验证器验证码 → 首页”。
- 注册默认由服务端关闭；关闭时没有失效入口。开放后才能进入邮箱验证和人工审核流程。
- 已登录用户从首页一个主动作继续最近对话，没有历史时能开始第一次对话。
- 消费者端只有“首页 / 聊天 / 我的”三个顶级入口。
- 聊天保留真实发送、历史、流式回复和失败重试，但不展示内部协议、模型、路由、记忆或调试信息。
- 管理后台只有“注册审核 / 账号 / 模型与路由 / 运行状态”，并且只进入 H5 构建。
- 核心页面通过目标尺寸的交互和截图验收，旧前端入口与未获批准的功能不再出现在活动路由中。

## 3. 重做边界

### 3.1 保留

- uni-app Vue 3、Pinia、现有 H5 构建与测试基础。
- 已验证的会话创建、消息历史、发送、流式事件归并、断线恢复和终态处理语义。
- 后端已存在且新版仍有消费者的 Provider、模型、路由、运行探测和账号会话能力。
- 跨租户隔离、会话 cookie、CSRF、安全日志、数据库约束等真实安全边界。
- 仓库内 SVG 图标方案；按新规范收敛为 `vc-icon`，不引入图标字体。

“保留”表示复用业务能力，不表示保留旧页面组件、布局、文案或视觉样式。

### 3.2 替换

- `App.vue` 的旧全局视觉入口、消费者与后台 Shell、导航定义和路由守卫表现层。
- 登录、首页、全部会话、聊天、我的及后台全部页面模板。
- 旧设计系统 CSS、旧色彩、旧卡片组合、旧错误文案和 Technical Alpha / 控制台式表达。
- 认证 store 的页面导向模型：改为只消费服务端返回的 `nextStep`，不在客户端猜准入状态。
- 首页与会话列表的数据模型：统一使用真实最近活动排序。

### 3.3 从活动前端删除

最终切换时，以下旧页面及其专用组件、store、API 包装和测试在引用归零后删除，不移动到 `legacy/`，也不
建立旧 UI 兼容层：

- 记忆、记忆详情、陪伴设置、同意、成年状态、数据、导出、帮助、举报、AI 说明、无痕默认。
- 旧的运行总览、模型、路由、系统状态四套后台页面骨架。
- 只验证旧 20 路由、旧四项底栏、旧准入流程或旧视觉实现的单元测试与 E2E。

这里只删除前端入口和无消费者的前端代码，不删除数据库中的历史用户数据，也不顺带拆除仍被后端真实流程
使用的安全、记忆或治理能力。Git 历史就是回退手段，不再复制一份旧实现。

## 5. 页面开发前必须完成的契约

### 5.1 认证状态机

前端只消费服务端返回的下一步，不从 local storage、旧 relationship 或页面 query 推断。对外至少需要
以下稳定状态：

- `TOTP_REQUIRED`：密码正确，输入 6 位身份验证器验证码。
- `AUTHENTICATOR_SETUP_REQUIRED`：审核已通过，但账号尚未设置身份验证器。
- `EMAIL_VERIFICATION_REQUIRED`：注册已提交但邮箱未验证。
- `REVIEW_PENDING`：邮箱已验证，等待管理员审核。
- `ACTIVE`：第二步验证完成，或账号和密码通过且可信设备仍有效，已建立会话。
- `DISABLED` / `REJECTED`：说明账号不可用，不进入消费者 Shell。

密码验证成功时，服务端先检查该账号的可信设备凭据：有效时可以直接签发正式 session cookie；不存在、过期或
被撤销时只签发短时、一次用途的认证 challenge，完成 TOTP、恢复码或首次设置确认后才签发正式 session。
challenge 必须由服务端过期和消费，前端只保存完成当前流程所需的不透明值。

最小 HTTP 契约：

| 契约 | 用途 |
| --- | --- |
| `GET /api/v1/auth/registration-status` | 返回服务端注册开关；默认 `enabled: false` |
| `POST /api/v1/auth/register` | 仅开关启用时接受邮箱和密码并触发真实邮件验证码 |
| `POST /api/v1/auth/register/verify-email` | 验证邮箱并进入待审核，不建立可聊天会话 |
| `POST /api/v1/auth/login` | 校验账号（用户名或邮箱）和密码；可信设备有效时建立会话，否则返回 challenge 与 `nextStep` |
| `POST /api/v1/auth/challenges/{challengeId}/totp` | 日常 TOTP 验证并建立会话 |
| `POST /api/v1/auth/challenges/{challengeId}/recovery-code` | 使用一次性恢复码并建立会话 |
| `POST /api/v1/auth/challenges/{challengeId}/authenticator-setup` | 首次设置时取得二维码内容、手工密钥；第一次调用创建待确认密钥 |
| `POST /api/v1/auth/challenges/{challengeId}/authenticator-confirm` | 校验一次 TOTP，启用身份验证器并返回一次性恢复码 |
| `GET /api/v1/auth/session` | 刷新页面时恢复当前账号、角色、准入和身份验证器事实 |
| `GET /api/v1/auth/trusted-devices` | 在账号安全中列出仍有效的可信设备 |
| `DELETE /api/v1/auth/trusted-devices/{deviceId}` | 撤销一台可信设备及其免验证码能力 |
| `GET /api/v1/admin/registration-requests` | 管理员读取待审核账号 |
| `POST /api/v1/admin/registration-requests/{accountId}/approve` | 通过审核；下次登录进入身份验证器设置 |
| `POST /api/v1/admin/registration-requests/{accountId}/reject` | 拒绝申请并返回结果 |
| `GET /api/v1/admin/accounts` | 账号列表与准入、安全状态 |
| `POST /api/v1/admin/accounts/{accountId}/authenticator-reset` | 清除身份验证器、撤销其会话，下次登录重新设置 |
| `PATCH /api/v1/admin/accounts/{accountId}/status` | 仅提供实际需要的启用/停用动作 |

实现约束：

- 注册开关由后端配置控制，默认关闭；前端隐藏入口不是关闭注册的安全措施。
- 未选择并接通真实邮件发送方之前，注册接口不得伪造“验证码已发送”，注册开关保持关闭。
- TOTP 密钥需要可恢复的服务端加密存储；恢复码只保存不可逆校验值，并且一次使用后失效。
- 重置身份验证器必须撤销现有会话，避免重置后旧会话继续有效。
- 可信设备使用独立的随机 `Secure`、`HttpOnly` Cookie，服务端只保存令牌哈希；有效期从签发时固定为 90 天，
  不因使用而顺延。普通退出只撤销当前 session；修改密码、重置身份验证器、停用账号或“退出全部设备”撤销
  该账号的全部可信设备。
- 现有 Owner 账号在切换时通过一次明确的邮箱回填迁移进入新流程，旧会话撤销，首次登录设置 TOTP；不保留
  用户名登录或双认证页面作为兼容层。
- TOTP 实现需要新增经过维护的 Go 生产依赖；编码前按仓库规则单独确认该依赖。Wot UI 已获产品确认。

### 5.2 最近会话契约

首页和全部会话共同消费一份会话摘要契约：

- 响应增加 `lastActivityAt`，服务端按 `lastActivityAt DESC, conversationId DESC` 排序。
- 使用同一排序键进行 keyset 分页，不能继续用“ID 越大就越新”代替活动时间。
- 首页请求少量结果并取第一项作为“继续上次对话”；全部会话使用同一接口分页。
- 每项只提供页面需要的标题、最后一句自然语言预览、角色和时间；消费者不接收模型、Token、路由或内部状态。
- 搜索只覆盖会话标题和摘要，不承诺对加密消息历史做全文搜索。若服务端尚不能给出完整搜索结果，则先不显示
  搜索框，不能把“仅搜索已加载一页”伪装成全局搜索。

`lastActivityAt` 是首页和会话列表的共同真实消费者，因此允许为它增加一项最小持久化字段或等价的可索引
查询；不借此重写整套会话模型。

### 5.3 单一陪伴关系

2026-09-01 已确认：新版没有多陪伴者选择器，也没有人格设置页。审核通过并完成身份验证器设置后，由服务端
自动创建唯一默认陪伴关系，用户直接进入首页或聊天。Stitch 中的“林夏”只是构图示例，不能硬编码为产品名称。

### 5.4 成年确认与必要同意

当前后端在创建回复前仍要求 `ADULT_VERIFIED`，向模型发出请求前还会核对服务条款、隐私政策、AI 内容、
第三方模型处理和敏感数据处理五项有效同意。这些不是旧页面的装饰状态，删除前端入口不能让真实服务端门槛失去
可完成路径。

当前注册关闭的上线阶段继续使用现有 Owner 已具备的成年与同意事实，不阻塞新版登录、首页和聊天。
2026-09-01 决定延期讨论未来注册的成年准入与必要同意方式。因此当前实施不得新增成年确认字段、改变现有安全门槛或
伪造核验结果，公开注册继续关闭。以后准备开放注册时再作产品决定并更新本文；如果届时要求第三方或证件年龄
核验，必须等真实核验服务可用后才能开放。

## 6. 跨端实施边界

- 当前交付目标是 H5。消费者组件、令牌、页面结构和 SVG 图标遵循 uni-app 与 Wot UI 的跨端写法。
- 当前只隔离两个已存在的 H5 差异：cookie/CSRF 请求发送，以及 Fetch SSE 实时传输。保留现有可注入接口，
  不新增“全平台网络框架”。
- 本轮不安装 `@dcloudio/uni-mp-weixin`，不配置微信 AppID、合法域名或小程序专用实时协议，也不报告小程序
  构建通过。
- 以后正式进入微信小程序交付时，再补最小请求适配和实时方案，并验证登录、首页、聊天冒烟；管理后台必须完全
  排除在小程序产物之外。

## 7. 实施阶段

必须按纵向可用切片推进。每个阶段达到验收条件后才能进入下一阶段；不得先批量创建空页面、占位组件或假数据。

### 阶段 A：契约与账号基础

**修改范围**

- `specs/openapi/virtual-companion.yaml`、`specs/catalog/go-v1-api-scope.yaml`，以及通过仓库生成脚本更新的产物。
- `backend/internal/auth/**`、`backend/internal/httpapi/**`、`backend/internal/store/postgres/**`。
- 新增最小数据库迁移和对应的数据库/HTTP 契约测试。

**交付**

1. 固定第 5 节的 `nextStep` 与认证 challenge 契约。
2. 增加邮箱、审核状态、身份验证器、恢复码、可信设备和注册开关所需的最小数据结构。
3. 让未审核、未设置身份验证器、停用账号在服务端无法获得可聊天 session。
4. 增加 `GET /auth/session`、管理员审核/账号接口和身份验证器重置。
5. 修正会话列表的最近活动排序与分页契约。
6. 按已确认决定自动创建唯一默认陪伴关系。
7. 保留现有 Owner 的成年和同意事实；未来注册的准入方式未确认前不改变现有服务端安全门槛。

**验收**

- 注册关闭时直接调用注册接口也会被服务端拒绝。
- 密码正确但未完成第二步时不能调用受保护聊天接口。
- 待审核账号不能创建会话或发送消息。
- TOTP 成功、恢复码单次使用、可信设备免验证码与撤销、身份验证器重置和 session 撤销都有后端测试。
- 会话最近活动排序在旧会话收到新消息后会正确前移。
- OpenAPI、scope catalog 和生成快照一致；生成文件不手改。

**停止条件**

- 邮件发送方未接通：注册保持关闭，但不阻止登录、TOTP、管理员和消费者主流程继续开发。
- TOTP 依赖未获确认：停止 TOTP 实现，不用自写算法或临时验证码替代。

### 阶段 B：前端基础与新骨架

**修改范围**

- `frontend/package.json` 与锁文件：只新增已确认的 Wot UI v2 兼容版本。
- `frontend/src/App.vue`、`main.ts`、`pages.json`、`app/**`。

## 8. 验证策略

验证只回答当前阶段的真实风险；输入未变化时不重复运行同一检查。

| 时点 | 最小验证 |
| --- | --- |
| 契约/后端阶段 | 对应 Go 单测、HTTP 契约测试、受影响数据库测试、OpenAPI/catalog 生成一致性 |
| 每个前端纵向切片 | 对应 Vitest、`pnpm --dir frontend type-check`、H5 页面交互检查 |
| 骨架、首页、聊天完成时 | 320×568、390×844、430×932 截图；底栏、safe area、焦点、键盘与溢出检查 |
| 后台完成时 | 1280×800、1440×900，以及窄于 900px 的抽屉/单栏检查 |
| 稳定候选 | 新核心 E2E：日常登录、可信设备登录、首次设置、待审核阻断、首页继续、首次聊天、发送失败重试、管理员审核 |
| 最终一次 | `pnpm --dir frontend test:run && pnpm --dir frontend type-check && pnpm --dir frontend build:h5`，随后一次 `bash scripts/check.sh` |

E2E 不延续旧 20 路由矩阵，也不为每一种理论错误组合建立旅程。小程序构建在本轮标记为 `NOT_RUN / 不在
当前交付范围`，不得写成通过。

视觉完成标准以 Stitch 构图和 `frontend/DESIGN.md` 为准，不追求生成图的错误像素。尤其阻断以下问题：

- 底部导航图标、文字、焦点环越界，或下方出现额外固定白色区域。
- 聊天输入区、键盘、导航互相遮挡。
- 中文被挤成逐字竖排，或页面产生横向滚动。
- 页面为了展示“完整性”重新加入无消费者状态卡、专业术语、假数据或未来功能入口。
