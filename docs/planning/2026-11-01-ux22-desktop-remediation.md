# UX-22 桌面沉浸玻璃整改单

> 2026-11-01 Claude 复核 UX-21 真实宿主截图（`.review-queue/UX-21/host/`，`ff5b0514`）后编写。执行规则沿用
> [UX-11 实施方案](2026-11-01-ux11-desktop-immersive-plan.md) 第 1 节约束与 2.1 节 Goal 方式；本文与 DESIGN.md 第 16 节冲突时，
> 以本文第 2 节给出的新数值为准，并由 R0 先同步回 DESIGN.md。

## 1. 为什么测试没发现

1. 视觉判断由实现者自己完成（「逐张复核」），没有对照选中的 B 参照图，也没有独立复核。
2. 自动检查只覆盖内容列内部重叠、手机像素和性能，没有检查**面板之间是否重叠**、**主要操作是否点得到**、**侧栏选中态是否正确**。
3. 样板与真实宿主不同：九个酒馆抽屉不在样板里，真实宿主才暴露问题。
4. 规范本身有错（Claude 责任）：1440 宽度下四栏总宽 1504px 放不下；极光与玻璃数值过于保守，做不出 B 的效果。

## 2. 问题与整改（按影响排序）

### P0

**R1 聊天四栏在 1440 放不下，角色面板盖住对话**（1440 浅 / 深 `chat.png`）
- 现象：角色面板浮在对话面板上，盖住顶部按钮与输入区发送键；对话只剩约 500px。
- 新规则（替代 DESIGN 16.3 / 方案 6.1 对应条款）：
  - ≥ 1600：侧栏 200 + 列表 320 + 对话（≥ 560）+ 角色面板 340，默认展开。
  - 1180–1599：角色面板默认**收起**；打开时会话列表让位，对话 + 面板并排（1440 对话约 830px），关闭面板后列表恢复；**不得浮层覆盖**。
  - 状态：2026-11-01 Claude 已热修（`desktop/chat.css` 断点、`character-panel.js` 默认展开阈值 1600）。
  - 744–1179：维持方案 6.1（面板以浮层出现，但浮层内容不能盖住输入区：浮层高度到输入区上沿为止，或打开时输入区左移让位）。
- 验收：任何宽度、面板开或关，对话标题栏全部按钮与输入区「+ / 输入框 / 语音 / 发送」中心点 `elementFromPoint` 命中自身。

**R2 沉浸效果不足：整体发白、深色发平**（所有页面）
- 根因：面板覆盖约 95% 窗口，极光只能透过 36% 透明度的面板露出；光斑颜色过淡。
- 新数值（同步写回 DESIGN 16.1 / 16.2）：

| Token | 浅色 旧 → 新 | 深色 旧 → 新 |
|---|---|---|
| `--vc-aurora-alpha` | .45 → **.90** | .55 → **.85** |
| 光斑尺寸 | 70vmax → **60vmax**（三个光斑分布到左上、右中、下中，保证每个面板背后至少有一个） | 同 |
| 默认光斑色 | 桃 `255,150,120`、薰衣草 `170,135,255`、天蓝 `100,165,255` | 同色，亮度不变 |
| `--vc-glass-1` 侧栏 | .42 → **.30** | .46 → **.36** |
| `--vc-glass-2` 面板 | .64 → **.46** | .60 → **.44** |
| `--vc-raised` 内卡 | .66 → **.72** | .06 → **.08** |
| `--vc-rim` | 不变，另加外光 `0 0 0 1px rgba(255,255,255,.25)` | 外光 `rgba(255,255,255,.06)` |

  - 阅读区（聊天正文列、表单）若对比度不足 4.5:1，只给**文字所在的内卡 / 阅读列**加 `--vc-raised` 底，不回调面板透明度。
- 验收：1440 截图与 `D1-B-light-1.png`、`D6-B`、`D7-B` 并排放进 NOTES；在面板空白区域取样，饱和度（HSL S）浅色 ≥ 18%、深色 ≥ 15%（`check.mjs` 断言）；正文对比度 ≥ 4.5:1。

### P1

**R3 侧栏选中态与设置入口**（`settings.png`、`tavern-*.png`、`model-home.png`）
- 设置页与酒馆页侧栏仍高亮「聊天」。改为：在设置内时高亮底部「设置」，五个目的地均不高亮。
- 底部改为：头像 36（当前用户）+「设置」使用齿轮图标（DESIGN 16.3），不用人形图标。
- 验收：每个目的地与设置页，侧栏恰好一项 `aria-current="page"`，且是当前位置。

**R4 九个酒馆抽屉未适配**（`tavern-*.png`）
- 现象：抽屉成为整页，设置分类列消失；旧版居中标签、整行滑杆、旧圆形返回与居中标题。
- 规则：抽屉内容在**设置右侧内容区**原位打开（分类列保留，当前分类高亮）；标题栏按 16.3（左标题、右操作）；
  宿主表单按 16.4 映射：标签左对齐进标签列，滑杆在控件列（最宽 360）右侧带数值框（160），说明文字改为 13px ink-2 放在行下；
  宿主图标按钮统一为 16.4 圆形按钮（40）。只写样式，不改宿主 DOM / 逻辑（DESIGN 第 12 节）。
- 范围大，按抽屉拆提交：AI 回复配置 → API 连接 → 提示词格式 → 世界书 → 人设 → 角色卡 → 扩展 → 背景 → 界面。

**R5 聊天消息呈现**（`chat.png`、`1024-light-chat.png`）
- 阅读列最大 720 在对话面板内居中；角色头像 36（不是 24），与首行文字顶部对齐；消息工具行紧贴消息下方、与正文左缘对齐（不要漂到右侧）。
- 输入区占位文字左对齐；语音、发送按钮常显（发送在空输入时为禁用态）。
- 标题栏：左侧头像 36 + 名字 + 灰色实例名，不用胶囊底；右侧「角色面板」「记忆」「更多」圆形按钮（40）。

**R6 角色面板**（`chat.png`）
- 头像 96 加氛围色光晕（16.6）；快捷动作改为 56 圆形按钮 + 13px 标签（参照 D1-B）；无数据的分节整体隐藏，不留大片空白，面板高度随内容。

### P2

**R7 角色页**（`characters.png`）：无头像时用名字首字 + 氛围色渐变底（不用灰底小写字母）；网格下方通栏的「雨夜旅馆」行需查明来源——不是角色就移出角色网格区域，或给出所属分组标题。

**R8 记忆 / 陪伴版式**（`memory-list.png`、`inbox.png`）：
- 标题与内容列左缘对齐（记忆页标题与筛选栏错开）；筛选列表用设置分类同款行样式，不用灰色块；搜索框与列表同宽。
- 陪伴右栏超出面板时右栏单独滚动并显示底部渐隐，不被面板裁切；空状态按 16.5（48 图标框 + 一句话）。

**R9 设置 › 账户**（`account.png`）：按 DESIGN 第 2 节显示头像行（用户名、密码、身份验证器），只用现有数据；删除与分类列重复的「账户与数据」入口行。

**R10 深色**：R2 完成后，用同一页面浅深色并排复核；深色面板不得发平成纯黑块，侧栏与面板之间要能分清层次。

## 3. 检查与流程补强

1. `check.mjs` 与真实宿主走查都加三类断言：
   - 外壳直接子面板（侧栏、列表、对话、角色面板、设置分类、内容）包围盒两两不重叠；
   - 每个页面的主要操作（标题栏按钮、发送、保存、返回）中心点命中自身；
   - 侧栏 `aria-current` 与当前位置一致。
2. 每个 R 项完成后，在**真实宿主**截 1440 / 1280 / 1024 浅深色到 `.review-queue/UX-22/<R 编号>/`，NOTES 放对应 B 参照图并排对比。
3. **视觉复核由 Claude 做**（Codex 不做视觉验收），全部 R 项通过 Claude 复核和 Owner 试看后才部署；部署前不再以「逐张复核」代替。
4. 执行顺序：R0（同步 DESIGN.md 数值）→ R1 → R2 → R3 → R5 → R6 → R4 → R7 → R8 → R9 → R10。
