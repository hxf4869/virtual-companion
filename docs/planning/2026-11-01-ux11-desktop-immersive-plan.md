## 1. 不可违反的约束（违反任一条即返工）

1. **手机端（视口 < 744px）像素不变**：本轮所有新增 CSS 必须挂在 `html[data-vc-layout="desktop"]` 之下；
   验收时 390 / 360 的干净状态截图与基线逐像素一致（第 7.2 节）。例外只有第 5 节列出的交互修复。
2. **不改宿主结构**：DESIGN.md 第 12 节全部有效——`#chat`、`#sheld`、`#send_form`、`.mes` 结构与滚动容器不动，
   不在 `.mes_text` 子树插节点，不给 Tavern Helper `.TH-render` / iframe 设高度或 `overflow:hidden`。
3. **不新增后端接口、表、迁移、依赖**。角色面板、记忆、陪伴等只用现有前端已调用的接口与数据；
   拿不到的数据就不显示那一块，**不造假数据、不加接口**。不新增 npm / CDN 依赖（Lucide 已有）。
4. **不用覆盖层改生产**：禁止再写 UX-10 样板那种对 `vcms-*` 的大量 `!important` 覆盖，
   禁止用 MutationObserver 在运行时改写生产 DOM（替换 toast、图标、未保存条等）。要改就改生产源文件本身。
   `!important` 只允许用于压过 ST 宿主自带的 `!important`，并在同行注释原因。
5. **字面值**：页面 CSS 不写字面颜色、字号、时长、z-index；只用 `--vc-*` token。新 token 先写进 DESIGN.md v4。
6. **文案**：面向用户的文字改动先改 `docs/planning/2026-10-30-companion-copy.md`，再同步代码。
   不加副标题、介绍段落、帮助图标、新手引导（DESIGN.md 3.2 继续有效）。
7. **一个 ID 一个分支 / worktree、一个写入 owner**；第 3 节的文件归属表是硬边界，跨文件需要先在 backlog 写 [问]。
8. 只用合成数据；不读 `config.txt`；不调用真实模型、语音、生产接口；不部署、不发布（生产发布仍暂停）。
9. 遵守 AGENTS.md：不删测试、不加 skip、不削弱断言、不手改 `specs/generated/**`。

## 4. 桌面视觉系统（已由 DESIGN.md 第 16 节定稿）

> 2026-11-01 UX-11 完成：本节数值与 DESIGN.md 第 16 节冲突时**一律以第 16 节为准**（例如侧栏 200、标签列 200、输入框 36、按钮 40、行高 44、提示条与确认框规格）。下文保留为设计意图说明。

UX-11 按 Owner 选中的图调整下表的数值，写进 DESIGN.md v4 新增的「桌面表现层」一节；**数值可以改，结构不能改**。
默认值按变体 B「沉浸景深」给出。

### 4.1 布局判定

- `shell.js` 根据 `chromeForWidth(innerWidth)` 在 `<html>` 上写 `data-vc-layout="desktop"`（≥ 744）或 `"mobile"`（< 744），随 resize 更新。
- 输入方式仍看 `pointer`：`(pointer: coarse)` 的桌面布局（平板）控件高度用 50、字号 17，其余规则相同。
- 断点：744–1179「紧凑桌面」、1180–1439「标准桌面」、≥ 1440「宽桌面」。

### 4.2 层次（从后到前）

| 层 | 名称 | 浅色默认 | 深色默认 | 说明 |
|---|---|---|---|---|
| L0 | 底色 | `#EEF0F6` | `#06070A` | 整窗 |
| L0 | 极光 | 3 个光斑，可见度 45% | 可见度 55% | 见 4.3 |
| L0 | 颗粒 | 内联 SVG 噪点，3% | 4% | 防色带 |
| L1 | 侧栏玻璃 `--vc-glass-1` | `rgba(255,255,255,.50)` blur 30px saturate 180% | `rgba(30,30,34,.48)` | 离窗口边 12px，圆角 24 |
| L2 | 内容面板 `--vc-glass-2` | `rgba(255,255,255,.72)` blur 40px | `rgba(22,22,26,.62)` | 圆角 24；面板间距 12；外阴影 `0 24px 60px` 浅 `.12` / 深 `.50` |
| L2 内 | 分组卡 `--vc-raised` | `rgba(255,255,255,.72)` 实色无模糊 | `rgba(255,255,255,.06)` | 圆角 16；**面板里不再套玻璃** |
| L3 | 浮层 `--vc-glass-3`（菜单 / 弹窗 / 提示） | `rgba(250,250,252,.86)` blur 40px | `rgba(36,36,40,.84)` | 外阴影 `0 30px 80px`；遮罩浅 `.22` / 深 `.50` |

- 所有玻璃：内顶高光 `inset 0 1px 0`（浅 `rgba(255,255,255,.7)` / 深 `.10`）+ 0.5px 描边（浅 `rgba(0,0,0,.06)` / 深 `rgba(255,255,255,.08)`）。
- **可读性下限**：L2 浅色透明度不低于 .72、深色不低于 .60；正文对比度按面板底色计算 ≥ 4.5:1。
- `prefers-reduced-transparency: reduce` 时所有玻璃改为对应不透明色，极光保留但降到 20%。
- 单一强调色 `#0071E3` 不变；危险 / 警告 / 成功色不变。手机端 token 全部不变。

### 4.3 极光（氛围背景）

- 实现：`E/desktop/aurora.js` 在 `body` 最底层插入一个固定定位容器（`--vc-z-backdrop: 0`，在叠层表登记），内含 3 个 `div`，
  每个用 `radial-gradient(closest-side, rgb(var(--c)) 0%, transparent 70%)`，尺寸 60–80vmax。**不用 `filter: blur`，不用 canvas / WebGL。**
- 颜色：光斑 1 = 当前角色 `--tint`；光斑 2 = `--tint` 色相 +40°（在 JS 里用 HSL 计算后写入变量）；光斑 3 = 强调蓝与紫的混合 `rgb(90,110,230)`。
  无当前角色的页面（设置、剧情列表等）使用默认氛围：光斑 1 = `rgb(120,140,255)`、光斑 2 = `rgb(255,170,150)`。剧情页使用案件封面取色。
- 动画：每个光斑 `transform: translate()/scale()` 循环漂移，周期 40s / 52s / 64s，`ease-in-out` 往返，位移 ≤ 6vw，缩放 1–1.15。只动 `transform`。
- 换角色：新旧两组光斑交叉淡化 900ms（用 spring 曲线）。
- 页面不可见（`visibilitychange`）时暂停动画；`prefers-reduced-motion` 时静止。

### 4.4 交互光效

- **指针高光**（`E/desktop/pointer-light.js`）：只作用于带 `data-vc-light` 的元素（侧栏项、会话行、角色卡、案件卡、设置分类行、按钮胶囊）。
  `pointermove` 用 rAF 节流，写 `--mx/--my`，元素 `::after` 渲染 `radial-gradient(160px at var(--mx) var(--my), rgba(255,255,255,.10), transparent)`（深色 .06）。不监听全局 mousemove。
- **悬停**：行与卡片背景提亮一级 + 高光描边；卡片上浮 `translateY(-2px)`、阴影加深，时长 standard，spring。
- **倾斜**：只用于角色卡与案件卡，最大 4°，立绘层视差 6px；离开时弹回。
- **选中透镜**：侧栏选中项是一块玻璃胶囊，切换时以 spring 滑到新位置（复用手机标签栏透镜思路）。
- **主按钮**：悬停加 `0 0 0 4px` 强调色 15% 光圈 + `0 8px 24px` 强调色 30% 投影；按下 `scale(.96)`。
- **焦点环**：2px 强调色 + 4px 强调色 25% 外光；`:focus-visible` 才显示。

### 4.5 动效清单（桌面）

| 场景 | 动效 | 时长 / 曲线 |
|---|---|---|
| 切换一级目的地 | 内容面板交叉淡入 + 上移 8px + 模糊 6px→0；侧栏透镜滑动 | 320ms spring |
| 列表 → 详情（会话→对话、角色卡→详情、案件卡→详情、设置分类→内容） | View Transitions API 共享元素（头像 / 封面 / 标题）；不支持时退回淡入 | 420ms spring |
| 角色面板展开 / 收起 | 宽度 0↔320 + 内容淡入，对话列同步让位 | 380ms spring |
| 新消息 | 用户消息从输入框方向上升 12px + 放大 0.96→1；角色消息沿用原版流式渐清 | 380ms |
| 弹窗 / 菜单 | 菜单从锚点缩放 0.9→1 + 模糊渐清；弹窗缩放 0.96→1 + 遮罩淡入 | 260ms / 320ms |
| 提示条 | 从面板顶部下落 8px + 淡入；退出上收 | 260ms |
| 骨架 | 从左到右高光扫过 | 1.6s 循环 |
| 数字 | 用量等统计数字首次出现时 0→值滚动 | 600ms ease-out |

- 只动 `transform` / `opacity` / `filter`（模糊只用于入场过渡，不常驻）。
- `prefers-reduced-motion`：位移、缩放、倾斜、指针高光、极光漂移全部关闭，统一 150ms 淡入淡出。
- 外观设置新增一项「减弱动态效果」（开关，存本机 `localStorage`，与回复样式同一处理方式）：开启时等同 reduced-motion，并把极光降到 20%。只在桌面显示。

### 4.6 性能预算（验收时测）

- 同屏常驻 `backdrop-filter` 表面 ≤ 4 个（侧栏、列表、对话 / 内容面板、角色面板）；列表行、分组卡不用模糊。
- 空闲时没有 JS 驱动的逐帧动画（极光纯 CSS）。
- 1440×900、Chrome Performance 录 5 秒空闲 + 5 秒滚动聊天：无 > 50ms 长任务，滚动时帧率不明显掉（录屏人工确认，写进 NOTES）。

## 5. 两端共用的交互规则（UX-12 实现；手机端也生效）

这些是 UX-10 审核里确认的缺陷，属于行为修复，允许改变手机端的对应交互（不改干净状态的像素）。

1. **叠层**：`.vcms-root` 在 `body.vc-ui` 下不得建立高于外壳的层叠上下文（去掉 `z-index: 30000` 的效果，改为遵守 `--vc-z-*` 表）。
   提示条、确认框、身份验证窗必须在任何页面之上。验收：打开模型页后触发确认框与提示条，`elementFromPoint` 命中它们自身。
2. **危险确认默认焦点**：`confirmAlert` 打开时聚焦取消类按钮；新增参数 `cancel`（默认「取消」）。Enter 不得直接执行危险动作。
3. **未保存修改**（页面、桌面弹窗、手机 Sheet 统一）：
   - 「干净」= 草稿与载入值相同。干净时保存按钮禁用；有修改时保存按钮可用，左侧出现文字按钮「放弃修改」。
     **删除「未保存的修改」文字标签**（它在 390 和桌面标题栏都会挤坏布局）。
   - 有修改时离开（返回、切换侧栏目的地、切换设置分类、取消、关闭弹窗、点遮罩、下拉关闭 Sheet）→ 统一确认框：
     标题「放弃更改？」、正文「关闭后本次输入将丢失。」、按钮「继续编辑」（默认焦点）/「放弃」（红）。
   - 模型页从供应商 / 模型层返回时同样适用；选「放弃」把草稿恢复为载入值。
   - **手机 Sheet 只保留一个提交方式**：右上「完成」= 有修改时保存（等待中显示「保存中…」并禁用），无修改时关闭。
     删除 UX-10 样板加在 Sheet 底部的通栏「保存」。
   - **Esc**：只关闭最上层的菜单 / 确认框 / 弹窗（有修改按上面规则确认）；**页面本身不响应 Esc**（去掉模型页 Esc 关闭整页）。
4. **操作提示**：全局单实例；成功 1.8s 自动消失；失败常驻带关闭按钮。手机位置不变（顶部居中）。
   桌面：在当前内容面板的顶部居中、面板标题栏下方 12px，**不得盖住任何标题栏按钮**。
5. **共用影响确认**：点保存后若影响多个用途，弹出确认框（不再在页面底部插入提示块）：
   标题「同时影响 N 个用途」，正文列出用途名，按钮「检查一下」（默认焦点）/「仍要保存」。
6. **焦点**：页面层级切换后焦点移到新页面标题（`tabindex="-1"`）；返回后焦点回到打开它的那一行。弹窗关闭焦点回到打开者。
7. **等待态不跳宽**：按钮进入等待文案前锁定宽度（试听「正在生成语音…」/「暂停」同样适用）。

## 8. ADR-0010 要点（UX-11 撰写）

- 决定：未来 iOS / Android App 采用 uni-app（或同类）壳 + `web-view` 加载同一 ST Web 源；手机 UI 只有一套，即现在的手机网页布局。
- 壳只负责：安全区透传、系统返回键映射为网页内返回、麦克风 / 通知权限、文件下载 / 分享、后台恢复时刷新会话。**壳内不放业务逻辑与第二套状态。**
- 不做：原生重写聊天（会失去角色卡脚本 / Tavern Helper / EJS 生态）。
- App 立项前必须验证（沿用 DESIGN.md 第 15 节）：登录会话、系统返回、安全区、软键盘、音频 / 麦克风权限、文件与下载、卡片 / iframe 脚本、后台恢复。
- 本 ADR 不授权：开始写 App 代码、上架、对 Owner 以外的人提供服务（ADR-0009 §3、§4 继续有效）。
- 同步修改 DESIGN.md 第 15 节为引用 ADR-0010。

## 9. 附：UX-10 样板审核结论（2026-11-01，Claude）

已实测确认、本方案已覆盖的问题（括号为处理条目）：

1. 模型页确认框与「已保存」提示被 `.vcms-root{z-index:30000}` 盖住，焦点落在看不见的「放弃修改并关闭」上（UX-12 §5.1）。
